==========================================================
Date: 2026-11-23
Milestone: BC-13 (Alignment & Snapping Guides)
Type: investigation only. No production code was changed. Nothing was
committed or pushed.
Baseline: BC-12.5 committed (ba5133a).

Legend:
  [VERIFIED]   observed in the current code, or measured by the probe
  [PROPOSED]   design recommendation
  [ASSUMPTION] not verified; to confirm in the named checkpoint


1. EXECUTIVE SUMMARY
--------------------
- Layoutry already has a first-generation Free-layout snap (Checkpoint
  1.15.6.1.1) [VERIFIED]:
  - a pure engine, resolveFreeMoveSnap;
  - live use in the Free-child MOVE session only;
  - two simple guide lines;
  - a session-only "Snap" toggle in the Inspector's Layout section.
- It snaps one direct child to its parent's edges/center and to its direct
  siblings' edges/centers, read from the DOCUMENT (freeLayout), with an
  8px threshold.
- It has NONE of:
  - resize snapping;
  - nested, transformed or clipped targets;
  - equal spacing;
  - distance labels;
  - hysteresis;
  - a modifier bypass;
  - a Shift axis lock;
  - auto-scroll;
  - pointer-positioned insertion;
  - a persistent preference.
- The architecture is a good base, because every Free gesture already:
  - is a rAF-throttled pointer session;
  - writes px geometry live;
  - commits one Undo transaction;
  - restores the document on Escape.
  So BC-13 is mostly an engine rewrite plus targeted session integration,
  not a new interaction system.
Facts that shape the plan [VERIFIED]:
- There is NO Canvas zoom. The View-menu Zoom items are disabled
  placeholders, and screen px = CSS px. The zoom aspects of D3, D17 and
  D41 reduce to a scale seam of 1.
- Free geometry is plain px numbers (x, y, width, height), and min/max
  constraints are px numbers. The document model has NO calc(), min(),
  max() or clamp() expressions. D35 and D48 are satisfied by construction.
- There is no responsive viewport switching (D24 = the single Canvas
  width).
- A Free child's Canvas drag can't leave its parent. A Flow element
  dropped into a Free container (dnd-kit) and a Resource Panel insertion
  are both placed at the first free slot, NOT at the pointer. So D30 and
  D44 need new infrastructure.
- A pre-existing coordinate defect was found (probe, section 4.3). In a
  Free container with padding or a border, the stored "content-box"
  geometry, the rendered position and the guide position disagree:
  guides are off by paddingLeft − borderLeft (14px in the probe).
- pointercancel COMMITS the gesture in both Free sessions. D21 requires a
  restore.
Recommendation: READY WITH CONDITIONS — five owner questions (section 11).
None blocks starting BC-13.2 (the engine foundation), which assumes the
recommended answers.

3. EXISTING DRAG / RESIZE / INSERTION LIFECYCLE
-----------------------------------------------
[VERIFIED] Free move (useFreeChildMoveSession):
1. pointerdown:
   - the protection and transform-ancestor checks run (on a refusal: a
     notice, and the click still selects);
   - stopPropagation and setPointerCapture;
   - beginResizeTransaction;
   - startX/Y/width/height are read from node.freeLayout;
   - parentBounds = measureFreeContainerBounds(DOM parent);
   - siblings are read once from the document.
2. pointermove: the latest pointer is stored and a rAF commit scheduled.
3. Commit per frame:
   - raw = start + pointer delta;
   - if snapEnabled → resolveFreeMoveSnap → guides;
   - containment clamp;
   - setActiveSnapGuides + setFreeChildGeometryLive (a live document
     write).
4. pointerup / pointercancel → endSession:
   - cancel the pending rAF;
   - if it moved: the final commit + commitResizeTransaction;
   - otherwise cancelResizeTransaction;
   - clear the guides and release capture.
   pointercancel takes the same path, so it COMMITS.
5. Escape (window keydown, capture): restore the snapshot document and
   selection, cancel the transaction, clear the guides. stopPropagation in
   the capture phase keeps the Canvas's Escape-deselect from running
   (verified by reading the code; the BC-12 "Escape clears the selection"
   defect is the dnd-kit Flow-drag path, not this one).
[VERIFIED] Free resize (useFreeChildResizeSession): the same shape.
- The 8 directions; side handles never lock.
- Corner handles keep the start ratio when aspectRatioLocked.
- Min floors, and the containment clamp per edge.
- Resizing a Free CONTAINER also rescales its children (Scale/Clamp
  policy, applyFreeContainerChildGeometriesLive).
- No snap, no guides. pointercancel commits.
[VERIFIED] Insertion:
- catalog drag → dnd-kit (pointerWithin) → resolveDragEndInsertion →
  useInsertElement;
- into a Free container → first free slot (no pointer position, no
  preview);
- one insertElement = one history entry.
[VERIFIED] Cross-container:
- only via dnd-kit Flow moves (Canvas) or the Structure panel;
- entering Free → the auto slot (BC-12.2 planMove);
- a Free child can't be dragged out of its parent on the Canvas.


4. GEOMETRY AND COORDINATE-SYSTEM FINDINGS
------------------------------------------
4.1 Authoritative geometry (Q1) [VERIFIED]: node.freeLayout px, relative to
    the parent Free container.
    - Rendered = left/top/width/height px. Transforms are visual only (the
      document geometry ignores them).
    - Flow/Flex/Grid children have no stored position; their geometry
      exists only in the DOM.
4.2 Pointer → local CSS (Q2) [VERIFIED]: delta-based.
    - local = start freeLayout + (clientX − startClientX).
    - There is no absolute pointer → local mapping today, so nothing breaks
      when the Workspace scrolls. BUT scrolling during a drag (D41)
      changes the element's screen position without a pointer delta. The
      delta model would then drift: it needs a scroll-offset correction.
4.3 Origin mismatch (pre-existing defect) [VERIFIED by probe]:
    - Container: padding 20px, border 6px.
    - A child at freeLayout x=0 renders at the container's PADDING edge
      (6px from the outer edge): absolute positioning is relative to the
      padding box.
    - measureFreeContainerBounds returns the CONTENT box (clientWidth −
      padding), so containment treats x as content-relative.
    - FreeSnapGuideOverlay draws x=0 at outer edge + paddingLeft (20px),
      so the guide is 14px right of the real edge.
    - Effects in padded/bordered Free containers:
      - guides are off;
      - parent-center/right targets don't match the visual center/right;
      - children can't use the right/bottom padding area, but do overlap
        the left/top padding.
    - No effect when padding and border are 0 (the default Free
      container).
4.4 Zoom (Q3) [VERIFIED]: none. The threshold, guides and hit-testing are
    1:1. [PROPOSED] Carry a canvasScale = 1 factor in the engine API
    (screen-px threshold ÷ scale), so that when zoom ships later, D3/D17/
    D41 hold without a redesign.
4.5 Nested / transformed / clipped targets (Q4):
    - [VERIFIED] The document geometry can't express transformed or nested
      VISUAL bounds.
    - [VERIFIED] getBoundingClientRect gives transformed AABBs; the probe
      checked this on a 15°, ×1.2 nested container.
    - [VERIFIED] The moving element's own parent is never under a
      transformed ancestor (transformGeometrySafety blocks those
      gestures). So converting a target's screen AABB into the moving
      element's parent frame is a pure translation: rect − parent padding
      edge, at scale 1.
    - [PROPOSED] Targets come from DOM measurement once per session (plus
      targeted re-measurement); the moving element's own start geometry
      stays from the document (the existing transform-immune rule).
    - Clipping: intersect with every overflow-clipping ancestor's rect
      (computed style overflow ≠ visible), up to the Free context root.
      Fully clipped means excluded. New code.
4.6 Hidden elements [VERIFIED]:
    - isNodeAuthoredHidden (display none, or inherited visibility hidden)
      exists;
    - display:none elements have no box;
    - visibility:hidden elements do have rects, so they must be excluded
      explicitly.
4.7 Border box (D25) [VERIFIED]: getBoundingClientRect is the border box
    (margins excluded). freeLayout width/height is the border box
    (box-sizing border-box is assumed by the existing containment). Margins
    on Free children are composed by freeChildStyle; see risk R9.


5. CSS-UNIT AND EXPRESSION COMPATIBILITY (Q5)
---------------------------------------------
[VERIFIED]
- Free geometry: unitless px numbers, written by setFreeChildGeometry/Live.
- Size constraints: px numbers.
- CSS Position offsets (CssLengthValue, units px/%/rem/em/vw/vh) are not
  offered for Free children and are overridden by freeChildStyle.
- There is no calc(), min(), max() or clamp() anywhere in the model or
  schema.
So:
- D35: snapping writes px numbers exactly as today, without rounding (the
  existing commands don't round; keep that).
- D48: nothing to preserve; snapping never parses or writes CSS strings.
No conversion or parsing is needed. If a future checkpoint introduces
units for Free geometry, D35/D48 must be revisited (recorded as a guard
test idea).

7. CONFLICTS AND RISKS
----------------------
R1  HIGH — Free origin mismatch (4.3).
    - In padded or bordered Free containers, the guides, parent targets and
      containment disagree with the rendering.
    - BC-13 can't be correct (D2, D25, D29, D46 "no false guides") without
      one consistent frame.
    - Options:
      (a) Padding-box frame: x is relative to the padding edge (as
          rendered today); bounds = clientWidth/clientHeight (padding
          included); guides at the border inset. Existing children stay
          where they are; containment loosens slightly (children may use
          the padding area).
      (b) Content-box frame: render left = paddingLeft + x. This VISUALLY
          MOVES existing children in padded containers, Canvas and Export
          (a project-visible change).
    - Recommend (a). Q5.
R2  HIGH — cross-container Canvas drag doesn't exist (D44).
    - Building Free-child re-parenting on the Canvas is a feature beyond
      snapping: drop validation, the BC-12 shared move, geometry
      conversion and history.
    - Q2.
R3  HIGH — performance of live document writes.
    - Every frame writes the document (setFreeChildGeometryLive).
    - BC-12.5 showed that a change inside a container with ~1,000 children
      re-renders those children (~45ms on the Canvas in dev mode). A drag
      inside a large Free container may drop frames.
    - Measure in BC-13.3. Options: memoized element components; or a
      transient visual preview (a CSS transform on the moving node)
      committed at release. The latter conflicts with live Inspector sync
      and needs owner awareness.
R4  MEDIUM — pointercancel commits (D21).
    - Changing it to restore is a behaviour change (e.g. a touch gesture
      interrupted by the OS will no longer keep the partial move).
    - Implied by D21; no question.
R5  MEDIUM — insertion at the pointer (D30).
    - It changes today's behaviour (the first free slot) for catalog drops
      into Free containers. A click-insert keeps the auto slot.
    - Q3.
R6  MEDIUM — Shift (D42) vs Shift-click additive selection.
    - The click after a Shift-drag would also add to the selection
      (CanvasInteractionBoundary click handler).
    - Needs a post-drag click suppression (the dnd-kit pattern), only when
      the pointer actually moved.
R7  MEDIUM — Alt/Option bypass (D4).
    - Firefox on Windows/Linux shows its menu bar on an Alt key release.
      Needs keydown/keyup preventDefault while a session is active.
    - Electron: no native menu (Menu.setApplicationMenu(null)), so no
      conflict.
    - Linux desktop window managers may take Alt+drag for window moves
      (outside the browser's control; not a supported target per the
      desktop memory).
    - Ctrl/Cmd+Alt chords (CSS clipboard) need Ctrl/Cmd, so no conflict.
    - Verify in Firefox/WebKit in BC-13.3.
R8  MEDIUM — Workspace scroll during a drag (D20/D41).
    - The delta model drifts when the scroll container moves; it needs
      scroll-offset compensation and auto-scroll in the pointer sessions.
R9  MEDIUM — margins on Free children.
    - freeChildStyle composes spacing.margin into marginLeft/Top. The
      rendered border box is then offset from freeLayout by the margin,
      while D25 aligns border boxes. Snapping math must use the rendered
      box (freeLayout + margin) and write back freeLayout.
    - Verify with a probe in BC-13.2.
R10 MEDIUM — deletion during a drag (D47). An open transaction closed by
    the delete becomes its own history entry. The session must detect the
    missing node and cancel its transaction (restore = drop) before or as
    the deletion happens.
R11 MEDIUM — project switch during a drag (D49). The session refs survive
    replaceDocument. The sessions need a document-session check
    (documentSessionId exists in the store) and must end themselves.
R12 MEDIUM — container resizing with child scaling plus snapping (D5/D32).
    - Snapping the container's edge changes the children's scaled
      geometry.
    - Acceptable: the children follow the existing policy, and only the
      container edge snaps. Document it.
R13 LOW — the threshold changes 8 → 6 (D3). An existing-behaviour change,
    explicitly approved. Update resolveFreeMoveSnap tests.
R14 LOW — commitResizeTransaction pushes history even if the final
    geometry equals the start (moved and snapped back).
    - Add an equality check (no-op = no history, BC-12 consistency).
R15 LOW — the existing Inspector "Snap" toggle duplicates D36's control.
    Q4.
R16 LOW — transformed targets are AABBs (D23). Guides drawn at AABB edges
    of rotated elements look "outside" the shape. Intended per D23.
No BLOCKER: every conflict has a safe option.


8. PROPOSED SNAPPING-ENGINE ARCHITECTURE [PROPOSED]
---------------------------------------------------
8.1 Placement (Q6): canvas feature, pure modules, with no React in the
    engine.
    - canvas/utils/snap/snapTargets.ts: collect and normalize targets
      (DOM).
    - snapIndex.ts: per-axis sorted, deduplicated coordinate index with
      metadata (D34).
    - resolveSnap.ts: the move/resize/insert resolver, locks, tie-breaks.
    - resolveEqualSpacing.ts (D13/D14).
    - The existing resolveFreeMoveSnap becomes a thin adapter or is
      replaced. Tests migrate.
    - The editor store keeps only the ephemeral guide state (the same
      ownership split as today: editor owns the slot, canvas owns the
      math).
8.2 One engine for move, resize and insert (Q7):
    - Input: the moving box in the parent frame, an "active edges" set
      (move = all three per axis; resize = only the handle's edges;
      insert = as move), a constraint callback (containment, min sizes,
      aspect lock), the threshold in screen px, scale, the lock state and
      modifiers.
    - Output: the adjusted box, the winning guide per axis, spacing
      indicators and the next lock state.
    - Move, resize and insert differ only in which edges are active and
      how a delta is applied.
8.3 Locks and hysteresis (Q8): per axis {targetKey (axis coordinate +
    source ids), edge}.
    - A lock holds while the distance ≤ the release threshold (proposed
      1.5× the snap threshold, i.e. 9px at scale 1).
    - It is replaced only by a strictly closer candidate beyond a small
      epsilon (D45 tie: keep the lock).
    - It is dropped when its target becomes ineligible (D37).
    - It lives in the session's ref (not the store), so it never renders.
8.4 Equal spacing (Q9):
    - At session start, for each axis, sort the eligible boxes that
      overlap the moving box's perpendicular span (D14 "meaningful gaps":
      gap > 0, non-overlapping neighbours).
    - Compute the existing gaps between consecutive boxes.
    - Candidates: positions where the moving box's gap to its nearest
      left/right (top/bottom) neighbour equals an existing gap, or centers
      it between two neighbours.
    - Validate with the same threshold and hysteresis. The indicator shows
      the equal gaps with CSS-px labels.
8.5 Performance (Q14, D39):
    - Measure the targets once at pointer-down: one layout read of N rects
      (~1,000) — a few ms.
    - Per frame: a binary search in the sorted per-axis index for values
      within ±threshold (O(log N + k)), so no per-frame DOM reads.
    - Invalidation: a ResizeObserver on the Free context root plus a
      document change during the session (other than this session's own
      writes) → re-measure only the affected subtree (D26).
    - Guide state: write to the store only when the displayed guides
      change (as BC-12 did for indicators).
    - The likely bottleneck is R3 (live document writes re-rendering a
      large container's children), not the snap math. BC-13.3 measures it
      first; the BC-12.5 lesson is to profile before optimizing.
8.6 Editor-only guides (Q10): extend CanvasOverlay (FreeSnapGuideOverlay →
    lines, labels, spacing).
    - Overlay elements are outside [data-document-surface] and never in
      the document.
    - Hidden in Preview.
    - Fixed screen-size styles (1px lines, 11px labels).
8.7 Cancellation and navigation (Q11): a shared session-lifecycle helper
    for the Free move/resize/insert sessions.
    - One "cancel" path (Escape, pointercancel, lost pointer capture, node
      deleted, documentSessionId changed, Preview entered): restore the
      snapshot, cancelResizeTransaction, clear guides and locks, release
      capture, discard the pending rAF.
    - One "commit" path: process the final pointer, then commit only if
      the geometry changed (R14).
8.8 Modifiers (Q12):
    - Alt/Option: read per event (event.altKey); bypass application, keep
      detection (D22).
    - Shift: the dominant axis from the cumulative delta (|dx| vs |dy|,
      with a small dead zone), locking the other axis to its start; snap
      only on the free axis.
    - Conflicts: R6 (Shift-click), R7 (Alt menu). Ctrl/Cmd chords are
      unaffected. Resize has no modifiers today.
8.9 Preference (Q13):
    - A small editor preference module (localStorage key e.g.
      "layoutry.editor.snapEnabled", try/catch, the default true) feeding
      store.snapEnabled at start-up.
    - Global across projects and restarts (web: per origin; desktop: the
      app:// origin storage).
    - Never in project files (persistence test classification).
8.10 New infrastructure (Q15):
    - the DOM target collector with clipping and hidden filtering;
    - the coordinate frame (R1);
    - the snap index, locks and hysteresis;
    - equal spacing;
    - resize snapping;
    - distance labels;
    - modifier handling;
    - auto-scroll and scroll compensation in the pointer sessions;
    - pointer-positioned insertion with a preview;
    - the global preference and toolbar control;
    - lifecycle cancellation (pointercancel, delete, project switch);
    - (if Q2 = B) Canvas cross-container Free drag.
