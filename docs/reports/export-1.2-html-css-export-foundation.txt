==========================================================================================
SUMMARY
==========================================================================================
Layoutry now has a working, pure HTML/CSS Export Engine:

  exportHtmlCss(document, { mode: "standalone" | "separate", title?, lang? })
    -> { ok, files: [{ path, content, mediaType }], diagnostics }

How it works:
- It converts the authored document into a target-independent IR
  (ExportDocument), then prints a complete HTML5 page and a stylesheet.
- The stylesheet is either embedded (index.html) or separate
  (index.html + styles.css).
- It is deterministic and DOM-free. It has no React runtime, no Electron, no
  storage and no billing dependency.

Visual fidelity was the acceptance criterion, and it is measured in a real
browser:
- 8 fixtures were compared: 7 targeted fidelity documents plus every catalog
  entry on one page.
- In both output modes, the exported page reproduces the Canvas Preview with
  ZERO computed-style differences and ZERO geometry differences. That covers
  33,019 property checks over 371 elements per mode, with a maximum geometry
  delta of 0.00003 px.
- Screenshots are identical in size, with 99.98%–99.996% of pixels within
  8/255 per channel.
- Every remaining pixel difference was inspected. Each has a known cause that
  is not a style or geometry difference (section S).

The Canvas and the export compose CSS from the same code (V1):
- The per-element style composition and every Canvas default moved out of
  the React components into shared, pure design-rule modules.
- These are exposed by the new canvas public API (src/features/canvas/index.ts).
- Each default carries its Tailwind classes AND the exact CSS they compile to.
  A unit test compiles them with the repo's own Tailwind and checks that the
  two are equal.

Validation:
- typecheck, lint, Vitest (4,946 tests), browser Playwright (39), and the
  Next.js production build: all pass.
- Desktop/Electron results: section AE.

==========================================================================================
C. EXPORT IR DESIGN
==========================================================================================
src/features/export/types/exportIr.ts:

ExportDocument { root, defaultStyles, interactions, assets, diagnostics }

ExportElement fields:
- tag
- sourceNodeId
- styleKey: "node-N" in document order, "-media", "-shape-i"
- defaultStyles: shared ids
- declarations: ordered, validated CSS
- attributes: validated, unescaped; `true` means a boolean attribute
- authoredClassNames
- children

ExportText { text } holds raw text. Printers escape it.

The IR has no escaping, class names or files. It is independent of React,
Vue, Tailwind, Electron, storage and billing. It describes the authored page
as seen in Preview: transitions included, authored-hidden nodes carry
`hidden`, and dialog open state is taken from initial visibility.

Interaction bindings are kept (triggerNodeId, targetNodeId, trigger, action)
for EXPORT-1.3. Assets are listed with their kind (remote, relative or data).

==========================================================================================
D. HTML GENERATOR
==========================================================================================
printExportHtml.ts:
- Writes <!DOCTYPE html>, <html lang>, meta charset utf-8, meta viewport,
  <title>, then <style> or <link rel="stylesheet" href="styles.css">.
- The page root is the body's only child. No script is ever emitted.
- Real tags throughout: semantic sectioning, h1–h6, p, a, button, ul/ol/li,
  the full table family, form/label/fieldset/legend, input (9 types),
  textarea, select/option, figure/figcaption, img/video/audio/iframe (each
  inside its layout frame, as on the Canvas), svg with its shapes, dialog,
  hr and progress.
  - The page root and a legacy body become <div>.
  - blockquote, which has no Canvas renderer, becomes a <div> plus a
    diagnostic. This matches FallbackElement.
- Escaping: & < > in text; & < > " ' in double-quoted attributes. A textarea
  value with a leading newline is preserved.
- Void elements are printed without an end tag. Boolean attributes print
  bare. SVG children self-close.
- Attribute order is deterministic: id, class, then the element's own
  attributes in recipe order.
- Whitespace-safe formatting. React emits no whitespace between elements, so
  children are indented only where whitespace cannot render (a flex/grid
  container, judged by its final display, and table/select/svg). Elsewhere
  they are printed adjacently. This avoids gaps between inline-level
  siblings.

==========================================================================================
E. CSS GENERATOR
==========================================================================================
printExportStylesheet.ts prints in cascade order:
1. Base reset (exportBaseStylesheet.ts): a curated Tailwind v4.3.2 Preflight
   subset with MIT attribution. html antialiasing (from layout.tsx).
2. body = the shared page-surface default.
3. .ly-<default> rules actually used, in shared table order, plus @media and
   ::backdrop rules.
4. .ly-node-N rules in document order.

Values come from the recipes via serializeStyleObject. It is React's exact
rule: px for non-zero numbers except React's unitless list, zero stays "0",
and key order is preserved, so shorthand/longhand overrides resolve exactly
as React applies them. No rounding. Authored values are preserved verbatim.

Every static property the editor can author is covered:
- typography: family, size, weight, style, color, line height, letter
  spacing, alignment, decoration;
- backgrounds: color, image, size, position, repeat, attachment, linear and
  radial gradients;
- borders per side, radius per corner, clip-path shapes, multi-layer
  box-shadows;
- margin, padding, width, height, min/max sizes, aspect ratio;
- display, visibility, overflow (+x/y), pointer-events, cursor, user-select;
- position, insets, z-index;
- flex container/item, grid container/item;
- opacity and filters, transforms, transitions (Preview semantics);
- object-fit and object-position.

Text shadow: the editor has no text-shadow field, so none is exported. I
didn't invent one.

==========================================================================================
F. CSS SELECTOR STRATEGY
==========================================================================================
- Single-class selectors only, so there is one specificity and source order
  decides.
- .ly-<default-id> holds the shared defaults (e.g. .ly-heading).
- .ly-node-N holds one element's authored rule. N is the 1-based document
  pre-order index, so it is stable for identical documents and never derived
  from random editor ids.
- Inner media use .ly-node-N-media.
- The "ly-" prefix is reserved. Authored classes using it are dropped with
  reserved-class-name. No Tailwind classes and no editor classes ever appear
  in the output (asserted).

H. PAGE ROOT AND VIEWPORT SEMANTICS
==========================================================================================
- The Canvas page root (a flex column) becomes body > div.ly-page-root.
- The body carries the page surface, with margin 0 from the reset.
- The exported page is fluid and takes the browser's width. The 1440px sheet
  cap and the 2000px sheet minimum height are editor presentation and are
  not exported.
- Inherited page-root style (font family, size, line height, letter spacing,
  weight, smoothing, color-scheme, alignment, white-space, direction) was
  asserted equal in the browser for every fixture. Color was compared as the
  painted color.
- Viewport widths: the parity spec renders the export at the exact Canvas page
  width (800px). The unit tests exercise the output independently of width.
  No breakpoints exist in the model and none are invented. The only media
  query is the legacy body's existing sm: padding, reproduced verbatim.
- position: fixed and vw/vh resolve against the browser window on both sides.
  In the editor that window is not the page sheet, so these are documented,
  not "fixed" (AF).

  differences; 0 px geometry delta.

==========================================================================================
J. FREE LAYOUT FIDELITY
==========================================================================================
- Free children export as position: absolute with the authored left, top,
  width and height. Nothing is rounded.
- A Free host that is not itself a Free child gets position: relative, so it
  is the correct containing block. A nested Free host inside a Free parent
  uses its own absolute box, as on the Canvas.
- A Free container's retained flowLayout (e.g. grid) never leaks to its
  children. The child context is forced to "block", mirroring
  DocumentNodeRenderer (unit-tested).
- Paragraphs in a Free parent lose the prose measure, as on the Canvas.
- Browser result (free-layout fixture, including nested Free): 0 differences,
  0 px delta.

==========================================================================================
N. SECURITY AND VALIDATION
==========================================================================================
Order of checks:
1. Iterative limits scan: 20,000 nodes, depth 100.
2. The strict project schema.
Either failure is an error and no files are produced.

URL policy (exportUrlPolicy.ts) uses browser-equivalent scheme detection:
tab/newline are stripped and C0/space trimmed, which defeats "java\tscript:".
- link: http, https, mailto, tel, #, relative
- image / poster / background: http, https, relative, data:image/*
- media: http, https, relative, data:video|audio/*
- iframe: http, https, relative
- data:text/html, javascript:, vbscript: are refused everywhere. A link
  falls back to the Canvas's own "#".
- blob: and file: are non-portable and refused.

CSS (validateExportCssValue.ts):
- Every value is structurally checked: no ; { } < > \ ! @, no comments, no
  control characters, balanced parentheses and quotes.
- Colors must be a real color syntax: hex, rgb/hsl/hwb/lab/lch/oklab/oklch/
  color/color-mix, named colors, or keywords.
- font-family must be a valid list.
- background url() is re-checked and re-serialized with CSS escapes (< as
  \3c ).
- A dropped value equals what the browser drops on the Canvas.
- The embedded stylesheet is asserted free of "</style".

Markup:
- Generated attribute names are checked (no on*, strict syntax; data-*/aria-*
  allowed).
- An id containing whitespace is dropped. A duplicate id is kept with a
  warning.
- SVG paint must be none or a valid color.
- The reserved class prefix is enforced.

Tested with a hostile corpus parsed by DOMParser:
- script injection in text, attributes, id, class, title, textarea, CSS
  color and font-family, background url and SVG paint;
- obfuscated javascript:, data:text/html links and frames.
Result: no <script>, no on* attribute, no executable URL, one <style>, and
every drop reported. Plain javascript: is already refused by the project
schema (asserted).

Deep (100) and maximum-size (20,000) documents export. Over-limit documents
are refused before any recursion.

R. VISUAL PARITY TEST METHODOLOGY
==========================================================================================
1. Translation — documentDefaultStyles.test.ts: Tailwind compile vs
   declarations.
2. Structure — canvasExportParity.test.tsx (jsdom):
   - the real Canvas components are rendered in Preview;
   - for every node, the test compares tag, inline style (per longhand,
     through the same CSSOM), default classes, attributes, text, inner
     media, SVG shapes and the selected option.
   Known Canvas-only artifacts are excluded by name, with reasons:
   - readonly guard, `open` / `hidden` runtime state;
   - React's `muted` property and option selection;
   - React's value="" on toggle inputs;
   - SVG user-select.
3. Rendering — e2e/export-visual-parity.spec.ts (Chromium, Playwright):
   - Each fixture is imported into the real editor via project import, and
     Preview is entered.
   - The page sheet is pinned to a whole-pixel width (800px content). The
     editor window is nudged until the page sits on whole pixels. This is
     presentation width only.
   - The page root is screenshotted with animations disabled and the caret
     hidden.
   - The export is rendered in a clean page at width 800 in both modes:
     same browser, same device scale factor, same fonts, offline data:
     assets only.
   - For every element (including inner media and SVG shapes), the test
     compares the bounding rectangle (tolerance 0.5px) and 89 computed
     properties.
   - Colors are compared as painted RGBA, because the app's CSS build
     rewrites theme oklch() values as equivalent lab() values. This was
     confirmed in .next output.
   - Box-shadow ignores Tailwind's transparent zero layers.
   - The inherited page-root style is compared, plus a pixel diff with a
     diff image.
   - Thresholds:
     - zero style or geometry differences;
     - identical screenshot size;
     - at least 99% of pixels within 8/255.
   - Nothing is masked, blurred or excluded from the pixel comparison.
   - Results, screenshots and diffs go to test-results/export-parity/.

Every residual difference was located on diff images and explained:
- 16 px in every fixture: the editor sheet's 6px rounded border curves into
  the page's two top corners. This is editor chrome inside the Canvas
  screenshot clip.
- Gradients (box-styles, the 4.8% sub-tolerance pixels): Chrome's gradient
  dithering depends on the element's absolute position on screen. The values
  are equal within 8/255.
- Anti-aliasing of a few edge pixels on curves and diagonals (the image
  circle, the 50% radius, the dotted-border corner, the SVG star's inner
  edges): the geometry and colors are identical (0 differences) while edge
  rasterization differs by layer. This is a browser rendering limitation, not
  a style difference.
- Catalog: the 3 empty image cards show the editor-only placeholder icon on
  the Canvas, which export intentionally omits (missing-media-source).

Initial run, before the harness fixes (not export defects):
- The theme color notation (lab vs oklch) was solved by comparing painted
  color.
- Rects for <option>s with no layout box were skipped.
- A half-pixel sheet offset was solved with whole-pixel positioning.

==========================================================================================
U. DETERMINISM AND PERFORMANCE
==========================================================================================
Determinism:
- Identical documents give byte-identical files in both modes. This also
  holds for rebuilt documents and documents whose object keys are reversed.
- The input document is never mutated. There are no timestamps or random ids
  in the output.

Performance (Vitest, Node, this machine; exportHtmlCss including schema
validation):
- small fixture: 1.0 ms, 6.1 KiB
- 81-entry catalog: 11.3 ms, 83.9 KiB
- 2,000 nodes: 59 ms, 343 KiB
- 20,000 nodes (the project maximum): 463 ms. HTML 1.56 MiB, CSS 1.91 MiB,
  heap delta about 71 MiB (transient).
- depth-100 document: 3 ms

The traversal is single-pass (plus the iterative limits scan and the schema
parse). No worker was added. If an export UI needs it, a 20,000-node export
(~0.5 s) belongs in a worker. That is documented.

==========================================================================================
AF. KNOWN LIMITATIONS
==========================================================================================
- Interactions and the modal dialog are static only (EXPORT-1.3). Nine
  catalog entries are affected (M).
- There is no responsive model, so no responsive output.
- vw/vh and position: fixed resolve against the editor window on the Canvas
  and against the real viewport in the export. These differ by design.
- Authored font families are not loaded on either side.
- img alt comes from the display name (the Canvas behavior). A real alt field
  needs a schema change.
- Not reproduced, because they are Canvas-only React artifacts:
  - value="" on value-less toggle inputs;
  - muted set as a property rather than an attribute.
- Authored classes are verbatim. On the Canvas, tailwind-merge can let an
  authored class that names a Tailwind utility override a default. Export
  never does. This is rare and documented.
- Remote and relative assets are referenced, not packaged (no ZIP in scope).
  Relative paths are reported.
- Iframes have no sandbox attribute (no model field; product decision from
  DESKTOP-0.1).
- A 20,000-node export takes about 0.5 s on the main thread.
