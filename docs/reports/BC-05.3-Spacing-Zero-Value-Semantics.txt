LAYOUTRY — BC-05.3: SPACING ZERO-VALUE SEMANTICS
================================================
Date: 2026-11-10
Type: CSS correctness fix + data-model compatibility (project format 2) + regression tests
Base: HEAD af9e256 (BC-05.2)
Status: implemented and validated; NOT committed


1. EXECUTIVE SUMMARY
--------------------
Margin and padding now distinguish four states that used to be one:

| State                 | Stored                  | CSS written         | Inspector shows                        |
|-----------------------|-------------------------|---------------------|----------------------------------------|
| Unset                 | side absent             | nothing             | the rendered value, no dot, no reset   |
| Authored 0            | side = 0                | `padding-left: 0`   | 0, blue dot, reset available           |
| Authored non-zero     | side = n                | `padding-left: npx` | n, blue dot, reset available           |
| Effective / computed  | not stored              | —                   | shown for unset sides only (measured)  |

What changed:
- The model (types/spacing.ts):
  - every side of `spacing.margin` and `spacing.padding` is optional;
  - both boxes are optional;
  - 0 is a real value.
- Canvas, Preview and Export (all go through `elementPositionStyle`) write every authored side, 0 included, and nothing for an unset side.
- The project format went from 1 to 2, with a format 1 → 2 migration that removes the old zeros. Old projects therefore render, and export, byte-for-byte as before. This was verified on both frozen legacy fixtures (section 10).
- Inspector:
  - unset padding sides show what the element renders (a button's 8 / 16), not 0;
  - the reset button and the state dot follow authored state, never "value ≠ 0";
  - in the unlinked view each side has its own state dot and its own reset ("Reset padding left").
- Reset removes the authored value: one side, or the whole box. Undo brings an authored 0 back exactly.
- Multi-selection: unset and authored 0 now read as "Mixed", and writing 0 to an unset box is a real change.

All acceptance criteria are met. Two items need a product decision (section 20):
- whether to prompt before re-saving an old native file in format 2;
- the multi-selection display of an unset padding.

QA recommendation: READY FOR QA.


2. ROOT CAUSE
-------------
The defect is in the data model, not in a stray truthiness check.

- types/spacing.ts (format 1):
  `interface EdgeValues { top: number; right: number; bottom: number; left: number }`
  - Four REQUIRED numbers per box, and `spacing` holds both boxes.
  - The model therefore had no way to say "unset", so 0 was used as the unset sentinel. A comment in InspectorSpacingSection said so: "all-zero counts as unset, matching the spacing model's own documented zero default".
- canvas/utils/elementDimensionsStyle.ts (`elementPositionStyle`, used by the Canvas, Preview and Export alike):
  - `if (spacing.padding.top !== 0) style.paddingTop = …`, and the same for every side;
  - margin left/top used the composed `offset + margin`, written only when `!== 0`;
  - so an explicit 0 could never reach CSS.
- InspectorSpacingSection:
  - `isSet = top !== 0 || right !== 0 || …`, so Reset was unavailable for an explicit 0;
  - an unset box was displayed as 0, so a button rendering 8 / 16 padding showed "Padding 0";
  - Reset committed ZERO_EDGES (all zeros);
  - editing one side committed all four sides.
- bulkCommands.setElementsSpacingAllSides: a no-op when every side was already 0, so writing 0 to an unset box did nothing.
- InspectorBulkSpacingSection: the row was always "set", and unset could not be told apart from 0.
- A second, general cause, found while testing Case A: useInspectorEditSession started a session only from React's onChange.
  - React drops onChange when the text doesn't change.
  - So selecting a displayed "0" (unset margin) and typing 0 authored nothing.
  - The same applies to any unset property that shows its rendered value (e.g. typing 30 over an unset H1 font size that shows 30).

The search for `value || fallback`, `if (value)` and `Boolean(value)` turned up no other spacing paths:
- the Free-layout padding arithmetic in spacingCommands uses the numbers directly;
- the recipe's `!node.spacing` is a presence check, kept on purpose (section 4).
No blind replacement was done.


3. OLD vs NEW DATA REPRESENTATION
---------------------------------
Old (format 1):
  "spacing": { "margin":  { "top": 0, "right": 0, "bottom": 0, "left": 0 },
               "padding": { "top": 8, "right": 0, "bottom": 8, "left": 0 } }
  → every 0 meant "no declaration".

New (format 2):
  "spacing": { "padding": { "top": 8, "bottom": 8 } }   (same rendering as above)
  "spacing": { "padding": { "left": 0 } }               (authored padding-left: 0)
  "spacing": {}                                         (record kept, nothing authored)

TypeScript:
  type EdgeValues = Partial<Record<"top"|"right"|"bottom"|"left", number>>;
  interface ElementSpacing { margin?: EdgeValues; padding?: EdgeValues }

Helpers, all pure:
- `withEdgeSide`: set or remove one side; the box collapses to undefined once empty.
- `withSpacingBox`: replace or remove a box; the record is kept.
- `hasAuthoredEdge`: 0 counts as authored.
- `edgeValuesEqual`: absent ≠ 0.
- `uniformEdges`.
- `clampSpacingValue`: unchanged, 0–500.
- Removed: `clampEdgeValues` and `ZERO_EDGES`.

No parallel spacing system and no metadata flags: optionality in the existing record is the whole change. The Zod schema (editorDocumentSchema) mirrors it, and the compile-time drift guard confirms the types match.


4. MIGRATION / COMPATIBILITY STRATEGY
-------------------------------------
A version bump was necessary:
- in a format 1 file, 0 means "unset";
- in the new model, 0 means "authored";
- the same bytes `"left": 0` cannot mean both;
- so only the version number can tell them apart.

The existing PROJECT-1.5 migration chain was built for exactly this: "Format 2 will add { from: 1, migrate }".

Format 1 → 2 (projectFormatMigrations.ts, `migrateSpacingZerosToUnset`):
- For every node at every depth, iteratively:
  - remove every spacing side that is exactly 0;
  - then remove every box left empty;
  - keep non-zero sides exactly.
- The spacing record itself is always kept, even when empty. In format 1, the mere presence of `spacing` switched the pre-3.5 container default padding (`p-8`, 2rem) off. elementStyleRecipes still uses `!node.spacing` for that, so keeping the record keeps those containers at padding 0.
- Policy, deterministic: no format 1 zero is reinterpreted as an authored override. That is what minimizes visual change: format 1 never wrote a 0, so treating them as unset reproduces exactly what was rendered.
- Malformed spacing (not an object, or a "0" string) is left alone for the format 2 schema to reject, per the migration contract. The caller's object is never modified, because the dispatcher runs migrations on a clone.

Saving writes format 2. Builds before BC-05.3 refuse a format 2 file with "made by a newer version of Layoutry" and do not change it. See section 20 for the open "prompt before overwriting an old native file" decision.

Also updated:
- `CURRENT_PROJECT_FORMAT_VERSION = 2`;
- `projectFileV1Schema` renamed to `projectFileV2Schema`;
- docs/architecture/project-format.md (structure, format 2 vs 1, migration list, rollback);
- test/fixtures/persistence/README.md.

Copy/paste, duplicate, recovery snapshots and the browser library:
- In memory, nodes are cloned whole, so authored zeros and empty records carry over (section 11).
- Library and recovery records hold project text, which goes through `parseProjectFile` and therefore through the migration.
- The desktop main process checks only that `formatVersion` is an integer.
- The legacy library and recovery fixtures still open (their tests pass unchanged).

Factories (new elements): every composition that used to write ZERO_EDGES now writes the format 2 equivalent:
- zero sides omitted;
- `{}` where both boxes were zero;
- for example `{ top: 8, right: 0, bottom: 8, left: 0 }` → `{ top: 8, bottom: 8 }`.
Newly inserted elements therefore produce exactly the CSS they did before.


5. ZERO vs UNSET BEHAVIOR
-------------------------
- Typing 0 creates an authored 0. That includes typing 0 over a displayed 0, and "00".
- Rendering writes `padding-*: 0` / `margin-*: 0` for an authored 0.
  - Margin left/top compose with the resize-anchor offset as before, so an authored 0 plus offset -40 writes -40.
  - An authored 0 on a Free child is written too.
- An unset side writes nothing, so the element's default presentation applies:
  - button `padding-inline: 1rem; padding-block: 0.5rem`;
  - text controls;
  - the base stylesheet's `margin: 0`.
- No browser default values are hardcoded anywhere:
  - unset padding is measured from the Canvas;
  - unset margin shows 0, the shared base stylesheet's value (`*, ::before, ::after { margin: 0; padding: 0 }`, identical in Canvas, Preview and Export), and no Layoutry default presentation adds margin.
- Negative values are still not supported (clamped to 0, an authored 0), as before.
- Decimals are kept (2.5 is stored as 2.5).


6. INSPECTOR DISPLAY BEHAVIOR
-----------------------------
- A new hook, `useRenderedPadding(nodeId)` (inspector/hooks), follows the BC-01.4/5 `useRenderedTypography` precedent:
  - one `getComputedStyle` read of the Canvas element in a layout effect, re-run after document changes;
  - skipped entirely when all four padding sides are authored.
- Displayed value per side: the authored value, else the rendered value (padding) or 0 (margin).
- The box-model diagram shows the same values.
- The linked/unlinked toggle is derived from the displayed values.
  - It is re-derived on a selection change, and once more when the first measurement arrives.
  - So a button (8 / 16) opens unlinked with four truthful fields, instead of a misleading "all sides 0".
- Authored state is shown with existing conventions:
  - the row label dot and "Explicitly set" screen-reader text when any side is authored;
  - per-side dots in the unlinked view;
  - an unset side has no dot and its reset is hidden (opacity 0, disabled, as every reset).
- Layout fix found in testing:
  - at the narrowest Inspector width, the new per-side reset pushed the row past the panel edge;
  - the number input's intrinsic width is 184px and doesn't shrink in a flex row;
  - the side row is now a three-column grid (label | field | reset): `3.75rem | minmax(0, 1fr) | auto`;
  - the field column gives way down to the field's own min-width;
  - verified in a screenshot, and asserted by the e2e narrow-width test.
- No redesign: same fields, labels, link toggle and diagram.


7. RESET BEHAVIOR
-----------------
- Group reset: "Reset margin" / "Reset padding" remove the box (`setElementMargin/Padding(id, undefined)`). The spacing record stays.
- Side reset: "Reset {margin|padding} {top|right|bottom|left}", shown in the unlinked view. It removes only that side; the box collapses once its last side goes.

| Case | Result |
|---|---|
| A | unset → 0 authors 0; Reset becomes available |
| B | n → 0 stays authored |
| C | Reset removes the 0 |
| D | Undo brings the 0 back |
| E | Redo removes it again |
| F | Reset padding left keeps top, right and bottom, including an authored 0 (unit and e2e) |

- Composite exceptions: none. The linked "all sides" field writes four sides at once; that is the only composite write, and a later side reset still removes one side.
- BC-05.2 behavior is preserved and covers the new buttons:
  - every side row is a `data-inspector-reset-scope`, so pressing a side's reset while typing in that side cancels the draft (one Undo step);
  - resetting a different side keeps the typed edit;
  - a keyboard reset focuses that side's field.

--------------------------

- setElementsSpacingAllSides:

Focus stays in the row, as BC-05.2 requires. A side reset always lands on its field.

20. REMAINING LIMITATIONS
-------------------------
1. Old native files are re-saved as format 2 without a prompt.
   - Opening a format 1 file never writes it.
   - Saving writes format 2, which older Layoutry builds refuse ("made by a newer version"), leaving the file untouched.
   - project-format.md had recommended asking "update the file or Save As" on the first save of a migrated native file. That prompt is a product decision and is NOT implemented here; it is documented as open.
2. Multi-selection display of an unset padding: shows 0 (the baseline) with no state dot, and doesn't measure each element's own rendered padding. A single selection shows the true rendered values. Broad multi-selection work is out of scope by the brief.
3. Negative margins remain unsupported (clamped to 0), unchanged.
4. Linked view with mixed authored and unset sides:
   - the toggle is re-derived on selection (and first measurement), not after every edit, as before;
   - if a user links four different displayed values, the all-sides field shows Top's value, as it did before BC-05.3.
5. An unset padding side shows 0 for the single frame before the first measurement (one layout effect, before paint in practice), or permanently for a node that isn't rendered.
6. Group keyboard reset focus lands on the pressed "Linked" toggle (pre-existing BC-05.2 behavior, section 13).


21. KNOWN FAILURES
------------------
- WebKit, 2: native colour picker (input[type=color] missing in Playwright WebKit on Windows). Pre-existing, recorded in BC-01.6 E2. Unrelated to spacing.
