BC-06-H — FIXED (BC-06 defect, Medium)
- "Add link" copied the last link's hidden state. If the last link was
  hidden (Display none, Visibility hidden, or Opacity 0), the new link was
  invisible on the Canvas, in Preview and in the export.
- Fix: createNavigationLink drops exactly those three values. The rest of
  the look is still inherited.
- 2 tests fail on b57a6f9 and pass now.

PRJ-K1 — REGISTERED, NOT FIXED (pre-existing since PROJECT-1.2 / 0fcafaf,
not BC-06, Medium)
- The project shortcuts (Ctrl+S, Ctrl+Shift+S, Ctrl+O, Ctrl+N) are
  silently ignored while any `dialog[open]` exists in the page. That
  includes an authored Dialog element on the Canvas, which Design renders
  open.
- File › Save still works.
- Reproduced in Chromium on a fresh page (HTML › Dialog, then Ctrl+S) and
  in Electron with the PROJECT-1.1 file.
- Out of BC-06 scope, so it is raised rather than fixed (section 21).

Everything else verified as working:
- eligibility, add / remove / reorder, inheritance (including format 2
  zeros), limits, CTA and mixed content;
- interaction integrity on every audited removal path, including save and
  reopen;
- Undo/Redo stress, copy/paste/duplicate independence, persistence (v1,

Mixed-content ordering rule (documented in the BC-06.2 report, re-verified
here):

- Add inserts after the last direct link.
- Remove refuses non-links. A link nested in a Container is not a link of
  the nav (Remove of its id is refused and the node survives).
