3. TESTING POLICY (all checkpoints)
-----------------------------------
- Change-focused (the standing rule):
  - an impact map per checkpoint;
  - unit tests for every new pure function and schema;
  - component tests for new Inspector controls;
  - targeted Playwright specs for the new browser behaviour;
  - reuse earlier valid evidence.
- Engines: Chromium always. Firefox and WebKit only where the checkpoint
  touches engine-divergent CSS (vendor parts, backdrop, masks,
  animation, :where(), forms). Electron smoke only where the pipeline or
  media changes.
- Broader runs are allowed only where justified and stated:
  - 17.3: pipeline swap — the existing Canvas/export parity unit suite
    plus the BC-13 audit e2e spec plus one kitchen-sink screenshot
    parity spec × 3 engines;
  - 17.25: integration.
  - Nowhere else is a full suite the default.
- Every report lists: the exact commands, the reason, the area and the
  results.
