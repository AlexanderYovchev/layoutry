1. EXECUTIVE SUMMARY
--------------------
- The Free drag and the eight Free resize handles now share ONE
  interaction lifecycle (createFreeInteraction). Before, two hooks
  carried copies of it. The hooks keep only their geometry and snapping
  math.
- Cancellation (Escape, pointercancel, an unexpected lostpointercapture,
  window blur or a hidden tab, unmount, Preview, any non-modifier key):
  - restores ONLY the touched nodes' original freeLayout (node-scoped, not
    a whole-document restore);
  - drops the transaction: no history entry, the redo stack and the
    selection are kept;
  - clears the guides, locks, the queued frame and auto-scroll;
  - releases capture, and swallows the release click.
- Escape no longer clears the selection:
  - Free drag/resize: Escape is consumed in the capture phase;
  - the pre-existing BC-12 defect in the Canvas/catalog dnd-kit drag is
    fixed (Escape is claimed, and the release click swallowed).
  Verified in Chromium, Firefox and WebKit. Disabling the fix makes the
  test fail.
- Interrupted gestures (pointercancel, touch/pen, simulated) now roll
  back. Before, they committed partial geometry (R4).
- External invalidation (a store subscription):
  - the element or an ancestor deleted → the interaction stops, nothing is
    recreated, no drag entry, and the deletion's own history entry gets
    the committed geometry back;
  - the parent changed → it stops without writing into the new context;
  - the project replaced (documentSessionId) → nothing touches the new
    document;
  - entering Preview → rolled back.
- Edge auto-scroll (D20):
  - one rAF loop; the innermost scroll container that can scroll wins;
  - only while it reveals more of the element's own Free container;
  - it continues with a stationary pointer;
  - it stops on release, cancellation or the boundary.
  The Workspace (vertical) and nested scrollers (horizontal) were verified
  in 3 browsers.
- Scroll compensation (D41): the pointer delta is corrected by the
  container origin's shift every frame. The element stays under the
  pointer, with no drift.
- Snap targets refresh after scrolling (visibility/clipping, D19), after
  document changes, and when a referenced target moves, resizes, hides or
  disappears (D26/D37). Only the invalid axis lock is released; the other
  axis's lock is kept.
- The final pointer position is now also processed for the Free drag.
  Frames carry a generation token, so a frame queued by an ended
  interaction never writes.
- A drag/resize that ends unchanged records nothing.
- Tests:
  - unit: 53 files / 659 tests passed (33 new lifecycle/auto-scroll + 3
    command tests);
  - Chromium: 66/66 across the BC-13 and dnd-kit-related specs (new spec
    9 tests);
  - Firefox + WebKit: the lifecycle spec 18/18 (earlier 39/42 →
    fixed: 2 real issues, 1 timing threshold);
  - typecheck and ESLint clean.
- Performance: no drag regression (≈134–150 ms per move at 1,000
  elements; it was 150 ms). The lifecycle costs ≈0.5 ms per frame.
- Recommendation: READY FOR QA.

3. EXISTING LIFECYCLE DEFECTS DISCOVERED
----------------------------------------
[VERIFIED by reading code and/or tests]
L1 pointercancel committed partial geometry in both Free sessions (R4).
L2 Escape restored by writing the WHOLE transaction snapshot document
   back. This overwrote any other change made since pointer-down.
L3 Every Free child's move hook registered a permanent window Escape
   listener (1,000 elements = 1,000 listeners).
L4 Any history-pushing command during a gesture (Delete, Undo, Ctrl+N…,
   keyboard only, since the pointer is captured):
   - its pushHistory snapshotted the LIVE, uncommitted geometry, so undo
     brought the half-dragged state back;
   - the gesture's transaction stayed open and committed a second, stale
     entry at release.
L5 replaceDocument (new/open/close project) cleared the transaction, but
   the hook's refs survived. Later pointer events would have written into
   the new document (R11).
L6 The Free drag ignored the pointer-up position (the BC-13.4 resize fix
   had not been applied to dragging).
L7 Canvas/catalog dnd-kit drags: Escape cleared the selection (BC-12).
   In Firefox the release click after the cancel also changed it (found
   in this checkpoint's Firefox run).
L8 After any Escape cancel, the uncaptured release click landed on
   whatever was under the pointer and changed the selection (found in
   Chromium: resize → Escape → release on the empty Canvas deselected).
L9 The guide overlay measured its container only on mount/resize, so
   guides went stale when a NESTED scroller (or the Free container
   itself) scrolled.
L10 Not a code defect: Layoutry has no multi-page documents. "Page
   switching" has no code path; Pagination is a navigation component.
   The page-switch requirement is satisfied by the project-switch
   safeguards.


4. ESCAPE CANCELLATION IMPLEMENTATION (D21)
-------------------------------------------
- While an interaction is active, createFreeInteraction listens for
  keydown in the capture phase on window. Escape →
  preventDefault + stopPropagation → cancel("escape").
  CanvasInteractionBoundary's bubble listener never sees it, so the
  selection stays.
- The rollback is exact and node-scoped:
  - originals = the dragged/resized node's freeLayout, plus a nested Free
    container's children (it scales them) at pointer-down;
  - restoreFreeLayoutsLive puts back exactly those fields (undefined
    removes the field) and nothing else.
  Not done via Undo; the history is not touched.
- cancelResizeTransaction runs only if the transaction is still this
  interaction's own (a reference check).
- The redo stack is kept (tested: a future entry survives Escape).
- Cleanup: guides null, locks and snap context dropped, the queued frame
  cancelled, auto-scroll stopped (it lives in the same frame loop),
  listeners removed, capture released, the release click swallowed
  (swallowReleaseClick).
- Canvas/catalog dnd-kit drags (EditorApp): during a drag, a capture
  listener preventDefaults Escape (the Canvas deselect skips
  defaultPrevented) and swallows the release click. dnd-kit's own
  listener still cancels the drag.
- Outside an interaction, Escape is unchanged (no listener exists then).
- Verified:
  - unit: Escape after 3 frames; selection kept; future kept; event
    prevented and not bubbled; a resize Escape;
  - e2e (×3 browsers): drag, resize, and Canvas Flow drag;
  - regression: removing the EditorApp claim makes the Flow test fail.


5. POINTER CANCELLATION AND CAPTURE HANDLING
--------------------------------------------
- pointercancel → cancel("pointercancel"): rolled back, no entry.
  [VERIFIED unit for mouse/touch/pen — SIMULATED pointerType; the e2e
  test dispatches a synthetic pointercancel with pointerType touch.]
- lostpointercapture: a native listener on the capture element.
  - A normal release ends the interaction in pointerup first, so the
    lostpointercapture that follows finds it ended (a no-op).
  - An unexpected one cancels. [VERIFIED unit: both orders; commit
    exactly once.]
- window blur and document visibilitychange (hidden) cancel. [VERIFIED
  unit: blur.]
- Unmount (the element, its handles, or the Canvas leaving) cancels
  through the hooks' effect cleanup. [VERIFIED unit.]
- Finalizing happens once: state active → ended, and every entry point
  checks it. Duplicate cancel/commit calls are no-ops. [VERIFIED unit:
  blur + pointercancel + Escape + pointerup → still one clean rollback.]
- Capture is released in cleanup only if still held (it is
  try/catch-guarded for a detached element).
- [ASSUMPTION] Physical touch/pen devices were not available. Their
  pointer events take the same path.


6. AUTO-SCROLL ARCHITECTURE AND CONSTANTS (D20)
-----------------------------------------------
Scroll containers:
- collectScrollContainers(container) walks up from the dragged element's
  Free container (inclusive) and keeps every element whose computed
  overflow-x/y is auto, scroll or overlay, plus document.scrollingElement;
  innermost first.
- Collected once at pointer-down. Authored CSS is never changed.
Per frame (the same rAF loop as geometry):
- measureScrollers: each container's VISIBLE padding box (clipped by the
  outer ones and the window) and its remaining room per direction;
- planAutoScroll (pure): per axis, the first (innermost) container whose
  visible edge is within the band and that still has room → one delta.
  An ancestor takes over only when the inner one can't scroll. Never two
  containers on one axis.
- Reach limit:
  - scrolling only happens while the dragged element's own Free container
    extends beyond that visible edge, capped at its far edge;
  - so the Workspace no longer runs on past the container and leaves the
    element behind at its clamp (found in browser testing);
- applyAutoScroll, then the frame computes geometry with the new scroll;
- the loop continues while something scrolled (a stationary pointer keeps
  scrolling); pointer moves and scroll events also schedule frames.
Constants:
- AUTO_SCROLL_EDGE_PX = 40 (the activation band from the visible edge;
  past the edge = full speed);
- speed = 80 → 1200 px/s, quadratic in the depth into the band;
  time-based; a frame step is capped at 32 ms; minimum 1px per active
  frame.
Stops:
- release, cancellation, invalidation (all end the loop);
- leaving the band;
- the boundary (room 0);
- the container disappearing (isConnected check).
History: scrolling creates none; the interaction stays one transaction.
Verified:
- unit (7: speed ramp, directions, corner, boundary cap, innermost/
  ancestor priority, reach, time cap);
- e2e Chromium/Firefox/WebKit:
  - Workspace vertical, stationary pointer: it scrolls, the element stays
    under the pointer, it stops after release, one Undo;
  - Escape stops it at once;
  - a nested horizontal scroller scrolls (not the Workspace), stops when
    the element's container edge is in view, and never runs past it.
Horizontal Workspace auto-scroll is not reproducible: the page sheet
shrinks with the Workspace (measured at 1280 and 1100 px windows), so the
Workspace never overflows horizontally. Horizontal behaviour is covered by
the planner unit tests and the nested-scroller e2e.


7. COORDINATE RECALCULATION DURING SCROLLING (D41)
--------------------------------------------------
- The pointer→geometry model stays delta-based (start freeLayout +
  pointer delta).
- Every frame re-measures the Free container's local origin (padding-box
  corner, scroll included): compensatedPointer = pointer − (origin now −
  origin at pointer-down).
- This covers Workspace scroll, ancestor scroll, the container's own
  scroll, and any layout shift of the container, automatic or manual
  (wheel: scroll events schedule a frame).
- No accumulation: it is always relative to the pointer-down origin, so
  there is no drift (unit: scroll 60 → +60, then a 10px move → exactly
  +10).
- Containment is unchanged (the clamp after the snap); it is still one
  transaction.
- Snap targets are kept in the local frame (unchanged by ancestor scroll),
  so locks stay valid. The visibility/clipping change triggers a refresh
  (section 8).
- Guides: FreeSnapGuideOverlay now re-measures on scroll (trackScroll), so
  they follow nested scrollers. e2e: after auto-scroll revealed an
  offscreen target, the guide sits on its rendered edge (±0.5px).
- Zoom: the BC-13.2 scale seam is untouched (scale 1).
- [VERIFIED] the element stays within 4px of the pointer while the
  Workspace scrolls continuously: the one-frame React commit lag at
  ≈800 px/s.


8. TARGET VISIBILITY AND INVALIDATION (D19, D26, D37)
-----------------------------------------------------
- Eligibility is the BC-13.3 collector's rule:
  - border box ∩ the window ∩ every clipping ancestor's padding box →
    a partly visible target is kept (with its full border box for
    alignment); a fully clipped one is excluded;
  - hidden, 0×0 and the dragged subtree are excluded;
  - locked and Flex/Grid descendants are reference-only.
- Refresh triggers (the snap context is re-measured, never per pointer
  move):
  a) a scroll signature change (any scroll container's offsets):
     throttled to SNAP_REFRESH_INTERVAL_MS = 250 ms (it was 100; raised
     after profiling, section 14);
  b) any external document change (subscription): next frame;
  c) a referenced target changed: each frame re-measures only the 1–3
     targets the current result relies on (referencedTargetIds) plus the
     parent padding box. If one moved or resized by more than 0.5px, was
     hidden, or vanished → refresh at once.
- Lock handling: the engine's lock key is a coordinate. After a refresh,
  a lock whose line no longer exists simply isn't found, so that axis
  releases and re-evaluates; the other axis's lock is kept (D37).
- No global observer: only per-frame reads of the referenced targets
  during the interaction.
- [VERIFIED unit] a snapped-to target moves 30px:
  - the x lock is released (no stale snap, no guide);
  - the y lock is kept;
  - the next frame snaps to its new edge.
  A target hidden mid-drag stops being a target.
- [VERIFIED e2e] a target offscreen at pointer-down becomes usable once
  auto-scroll reveals it.
- Unsupported: targets inside a nested scroller that is itself scrolled
  by something other than the drag (e.g. a wheel over a sibling scroller)
  refresh via the throttled signature path (≤250 ms latency).


9. ACTIVE-ELEMENT DELETION SAFEGUARDS (D47)
-------------------------------------------
Two layers:
1. Keyboard policy: during an interaction, any non-modifier key first
   cancels it (rolled back), then reaches its handler unchanged. Delete
   therefore deletes the COMMITTED element: one history entry, whose undo
   restores the committed geometry. [VERIFIED unit and e2e.]
2. Safety net (a store subscription), for a deletion by any other path:
   - the node (or an ancestor) is missing → invalidate;
   - restoreFreeLayoutsInHistory rewrites the entries pushed during the
     interaction (pastLength at start) so they carry the committed
     geometry;
   - no document restore (nothing recreated); transaction dropped (no
     drag entry);
   - guides, frames, auto-scroll and capture cleaned up; the release
     click swallowed.
   [VERIFIED unit: deleting the element (and an ancestor, during a resize)
   → past = 1 (the deletion), later pointer events do nothing, and undo
   restores the ORIGINAL geometry.]
Interpretation note: the brief says "do not restore its original
geometry". Nothing is written to the live document after the deletion.
Only the deletion's undo snapshot is corrected, so that Undo brings the
element back as it was committed, never half-dragged. Selection
references: the deletion's own fallback selection is kept.
Parent changed externally: invalidate with a node-scoped restore. No
geometry is written into the new context; the move's entry is cleaned
the same way. [VERIFIED unit.]


10. PAGE/PROJECT SWITCHING SAFEGUARDS (D49)
-------------------------------------------
- Pages: none exist (L10).
- Projects (new/open/close, all through projectCommands →
  replaceDocument):
  - started from the keyboard (Ctrl+N/O…) → the keyboard policy cancels
    first, so the outgoing document gets its original geometry back
    BEFORE any unsaved-changes prompt or save reads it;
  - any other path → documentSessionId differs → invalidate without
    writing (the outgoing document is already gone).
  [VERIFIED unit: replaceDocument with a frame still queued → the new
  document is untouched, no history.]
- Preview entry → rolled back (subscription on editorMode). [VERIFIED
  unit.]
- Undo/Redo during an interaction: from the keyboard → cancelled first,
  then Undo/Redo act on the committed history. The buttons/menus need a
  click, which is impossible while the pointer is captured.
- The Snap preference survives cancellation (tested).
- [ASSUMPTION] The desktop shell has no native menu accelerators (per
  earlier checkpoints), so every shortcut is a DOM keydown.


11. FRAME SYNCHRONIZATION AND STALE-CALLBACK PROTECTION (D27)
-------------------------------------------------------------
- One rAF loop per interaction (it replaces each hook's own scheduling
  and is merged with auto-scroll): auto-scroll step → scroll signature →
  target validation/refresh → compensation → the hook's onFrame (latest
  pointer only).
- Generation token: every interaction gets a module-level generation, and
  a frame callback runs only if its generation is still the active one
  and the state is active. Queued frames are also cancelled on
  every terminal path. [VERIFIED unit: a frame queued before Escape, and
  one queued before replaceDocument, never write.]
- pointerup processes the release position (and modifiers) in one final
  synchronous frame, with no auto-scroll step, before committing. This
  applies to both drag and resize; the BC-13.4 resize fix is preserved.
  [VERIFIED unit: three un-flushed moves then a release → exactly the
  release position, one entry.]
- Own writes are flagged, so the subscription ignores them.


12. UNDO/REDO INTEGRITY (D12, D28)
----------------------------------
- Success: one entry (the pre-gesture transaction snapshot); Undo is the
  exact original and Redo the exact final (whole-document snapshots, no
  snapping recalculated). [VERIFIED unit and e2e.]
- No-op: if the pointer never moved, or the final geometry equals the
  originals (dragged away and back), the transaction is cancelled and
  nothing is recorded. [VERIFIED unit.]
- Cancellation: nothing recorded; past and future untouched. [VERIFIED
  unit: the future is kept; e2e: Undo stays disabled after Escape, after
  auto-scroll + Escape, and after pointercancel.]
- Scrolling and guides never touch history. [VERIFIED e2e: one Undo
  after an auto-scrolled drag.]
- Deletion/switch during a gesture: section 9/10 (no extra entry, no
  stale geometry in the history).


13. CLEANUP AND RESOURCE-LEAK PREVENTION
----------------------------------------
cleanup() runs exactly once per interaction and removes:
- the window keydown/keyup (capture), blur and scroll (capture)
  listeners; the document visibilitychange listener; the capture
  element's lostpointercapture listener;
- the store subscription;
- the queued frame (and with it auto-scroll);
- pointer capture;
- the guides (setActiveSnapGuides(null));
- the snap context and references;
- the modifier state (per interaction).
Then onEnd lets the hook reset the cursor/user-select, isDragging/
activeDirection, and its guide-dedupe key.
- [VERIFIED unit] the keydown/keyup/blur/scroll add and remove calls
  match after an interaction.
- The release-click swallow removes itself right after the next
  pointerup (tested: a later click goes through).
- EditorApp removes its Escape claim on drag end/cancel and on unmount.
- The Snap preference and other persistent preferences are never
  touched.


14. PERFORMANCE OBSERVATIONS
----------------------------
[VERIFIED] Chromium dev mode, a temporary probe (deleted), a 1,000-child
Free container (600×1400):
- Drag:
  - pointer-down + first move 259–381 ms;
  - per move median 134–150 ms, p90 233–265 ms (BC-13.3: 150/250);
  - release 270–400 ms (the commit, then the selection click
    re-render).
  - Profile over 31 frames:
    - lifecycle reads: measureScrollers 2.4 ms, referencesChanged
      9.7 ms, frame/reach 2.4 ms (≈0.5 ms per frame in total);
    - resolveSnap 0.6 ms; setFreeChildGeometryLive 36 ms;
    - versus ParagraphElement 1,310 ms and DocumentNodeRenderer 669 ms.
- Auto-scroll held 1.5 s:
  - only 13 browser frames (≈115 ms each: rendering-bound, P1);
  - 570 px scrolled;
  - the target refresh during scrolling cost 360 ms in total (≈15 ms
    each, about every frame with the 100 ms throttle) → the throttle was
    raised to 250 ms;
  - auto-scroll's own planning/applying ≈5 ms.
Conclusion: no regression; the lifecycle adds ≈0.5 ms per frame. Canvas
re-rendering (P1) remains the bottleneck, and it also makes auto-scroll
coarse (few frames, so larger steps) at 1,000 elements. No broad
rendering work was done here.

16. KNOWN LIMITATIONS AND DEFERRED REQUIREMENTS
-----------------------------------------------
- Keyboard policy: any non-modifier key ends an active Free drag/resize
  (rolled back) before its normal action. This is the termination policy
  for D47/D49/Undo during a gesture; the shortcuts themselves are
  unchanged.
- Autosave/recovery snapshots taken during a gesture can contain the
  live, uncommitted geometry (read-only paths; they are not changed
  here).
- Auto-scroll at 1,000 elements is coarse (≈9 frames per second,
  rendering-bound, P1).
- Horizontal Workspace auto-scroll can't occur (the page sheet is
  responsive). It is implemented and unit-tested, and the e2e covers the
  nested scroller.
- The element can lag the pointer by up to one frame during continuous
  auto-scroll (React commits after the scroll).
- The transformed-element resize snapping limitation (BC-13.4) is
  unchanged (it goes to BC-13.7 per the brief).
- Touch/pen are simulated only.
- The padded-container containment limitation (C1) is unchanged.
