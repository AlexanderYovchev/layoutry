==========================================================================================
SUMMARY
==========================================================================================
Interactive components now work in exported pages, without Layoutry, React, Next.js,
Zustand, Tailwind's runtime or Electron.

The editor has one generic interaction model:
- click bindings that show, hide or toggle another node;
- an authored "hidden in Preview" initial state;
- a native <dialog> that opens modally.
All nine targeted components are compositions of that model. So the export replays
Preview's own executor rather than inventing nine component behaviors. The replay
covers:
- the nearest-node click rule;
- outside-click and Escape dismissal of toggled, initially-hidden targets;
- the dialog's modal lifecycle.

How it works:
- buildExportBehaviors derives declarative behavior descriptors (ExportDocument.behaviors)
  from the bindings.
- The HTML printer writes them as generated data attributes.
- A constant runtime of 3,651 bytes (1,100 gzipped) applies them. It contains no
  document data.
- Static pages get no script at all.

Measured in Chromium against the editor's Preview, with real clicks and key presses:
- 31 scenario steps. Target visibility and focus match after every step in both output
  modes: 0 mismatches.
- 8 interaction-state visual snapshots × 2 modes: 0 computed-style differences and
  0 geometry differences. The in-flow page states are 99.9986–99.9989% pixel-similar.
- Floating elements (modal, drawer, toast) are anchored identically in their windows.
- The EXPORT-1.2 static visual parity was re-run: no regression (section X).

==========================================================================================
B. EXISTING INTERACTION AUDIT
==========================================================================================
Document model (editor/types/interactions.ts, previewVisibility.ts, both schema-validated):
- interactions[]: { id, trigger: "click", action: "show" | "hide" | "toggle",
  targetId: <internal node id> }. Click is the only trigger.
- initialPreviewVisibility: "visible" | "hidden".

Preview executor (useEditorStore.executeInteractionsForNode):
- applies the bindings in order to an ephemeral visibility map;
- skips missing targets;
- a hidden node is not rendered (it is unmounted).

Click dispatch (CanvasInteractionBoundary, one window "click" listener):
(1) Dismissal pass: each dismissible relationship (a click→toggle binding whose target
    is authored-hidden and currently shown) is hidden when the click lands outside both
    the trigger and the target.
(2) The bindings of the NEAREST node element only (closest [data-node-id], selectable
    tags) run. An ancestor's bindings never fire.

Escape (window "keydown"):
- hides the first open dismissible relationship (document order);
- with none open, it exits Preview. That is editor-only.

Dialog (DialogElement, Preview):
- showModal() on mount;
- a backdrop click (event.target === dialog) calls close();
- its Escape keydown stops propagation and the native cancel closes it;
- the native "close" marks it hidden.

Compositions (editor/factories): see C. No component-specific state exists anywhere
(no open/activeTab fields).

==========================================================================================
D. RUNTIME ARCHITECTURE
==========================================================================================
Export IR ─ buildExportBehaviors ─► ExportDocument.behaviors (descriptors)
  └─ printExportHtml / exportBehaviorAttributes ─► data-ly-* + aria-* on elements
  └─ EXPORT_INTERACTION_RUNTIME (constant) ─► <script> (standalone) | script.js (separate)

Runtime design:
- An IIFE in strict mode.
- One window click listener and one window keydown listener (delegation, no per-node
  click handlers).
- Per dialog target: click, keydown and close listeners. These mirror DialogElement.
- Init does one querySelectorAll per attribute kind.
- Behavior is selected by needsInteractionRuntime: there must be any trigger, or a
  dialog that is open at load.

==========================================================================================
E. BEHAVIOR DESCRIPTOR DESIGN (types/exportBehavior.ts)
==========================================================================================
ExportBehaviors {
  triggers:            [{ nodeId, actions: [{ action, targetToken }],
                          dismissibleTargetTokens, expandsTargetToken?, opensDialog }]
  targets:             [{ token, nodeId, kind: "element" | "dialog", initiallyVisible,
                          domId?, generatedDomId }]
  nodesInsideTriggers: [nodeId…]  (click boundaries for the nearest-node rule)
}

- Tokens are document-order integers. There are no executable strings, authored
  selectors or authored text.
- Bindings to missing nodes are dropped, as Preview's executor drops them.
- Triggers on the page root or legacy body are dropped with unsupported-trigger
  (Preview never resolves clicks to them).
- Non-keyboard triggers (div etc.) are flagged with non-operable-trigger.
- domId is the authored id if valid and unique; otherwise the generated
  "ly-target-<token>". It is omitted when the authored id is duplicated.
- The raw ExportDocument.interactions list is kept, for API compatibility.

==========================================================================================
F–N. COMPONENT BEHAVIOR (exported = Preview)
==========================================================================================
F. Dialog
   - Closed at load: no `open`. It stays closed unless a binding opens it.
   - Authored visible: the static `open` is a no-script fallback; the runtime removes it
     and calls showModal() at load, as Preview does.
   - Close, backdrop and Escape: native. Focus moves in and is restored natively.
   - Multiple dialogs are independent targets.
G. Modal
   - Open → showModal(); Close → close().
   - Backdrop click closes. Escape closes natively and never reaches the page.
   - The background is inert (native modal). Focus returns to the opener (verified with
     the keyboard).
H. Drawer
   - Identical runtime path to Modal.
   - Its authored fixed placement (right 0, top 0, bottom 0, 360px) is kept: it sits on
     the right edge at full window height on both sides.
   - No animations were added; the authored transition, if any, is untouched.
I. Dropdown
   - The trigger toggles the menu and aria-expanded follows.
   - Opening another dropdown closes it (outside-click rule). A click inside the menu
     keeps it open. An outside click closes it.
   - Escape closes the first open one and returns focus to the trigger if focus was in
     the menu.
   - No menu roles (there is no arrow-key menu model in the editor). Items are links;
     Tab reaches them.
J. Collapsible
   - Starts expanded (authored). Toggle collapses and expands; aria-expanded follows.
   - Not dismissible, exactly as in Preview.
K. Tabs
   - Each tab shows its panel and hides the others, within its own group only.
   - Panel content is preserved, since it is only hidden.
   - No tab roles or arrow keys, because the editor implements neither. This is
     documented, not invented.
L. Popover
   - An in-flow panel toggle with outside-click and Escape dismissal.
   - The Popover API is not used: the panel is in flow in the editor, and the top layer
     would change its layout.
M. Toast
   - Show appears at fixed bottom-right (24/24). Its own Close hides only that toast.
   - Two toasts never cross-interfere.
   - No auto-timeout and no live region, because the editor defines neither.
N. Dismissible Alert
   - Its Dismiss button (a native button, keyboard-operable) hides only its own alert.

==========================================================================================
R. RUNTIME SECURITY
==========================================================================================
- The runtime is a constant string. A test asserts it has no eval(, Function(,
  innerHTML, outerHTML, insertAdjacentHTML, document.write, timers, </script or <!--.
- The printer refuses to embed a script containing </script or <!--.
- Data reaches the runtime only via data-ly-* values that the printer writes from
  integers and the keywords show/hide/toggle. The runtime also ignores non-digit tokens
  and never builds selectors from data.
- Hostile document (script in text, attribute-breaking ids, a class mimicking
  data-ly-on-click, a hostile target id):
  - every data-ly-* value matches its strict grammar;
  - no on* attributes;
  - exactly one <script>, containing no document text;
  - the authored id is escaped and referenced verbatim.
- Invalid behavior metadata (an unknown action or trigger, or a selector-like targetId)
  is refused by the project schema as invalid-document.
- Cross-component targeting cannot happen: the token is the only handle.
- Duplicate ids: no aria-controls for that target; behavior is unaffected.
- Authored ids may no longer use the reserved "ly-" prefix (invalid-html-id), so
  generated ids cannot collide.

AI. KNOWN LIMITATIONS
==========================================================================================
- Hidden vs removed: identical look and layout. Form input typed inside a hidden-then-
  shown panel is kept in export, but reset by the Canvas's re-mount.
- Links inside components navigate in the export (the Canvas suppresses navigation while
  editing).
- No behavior beyond what the editor defines:
  - Tabs have no arrow-key or tab roles;
  - Dropdown has no menu roles or arrow keys;
  - Toast has no live region or timeout;
  - the Popover API is not used.
- Focus after a control hides its own container falls to the page (as on the Canvas).
- Standalone mode needs 'unsafe-inline' (or a hash) under a strict CSP; separate mode
  doesn't.
- Fixed elements on the Canvas can be painted under editor panels near the window edge
  (Canvas presentation, not export).
- The runtime needs <dialog>.showModal() (all current evergreen browsers); there is no
  polyfill.
