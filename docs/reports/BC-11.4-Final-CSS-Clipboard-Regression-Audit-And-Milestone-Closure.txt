BC-11.4 — Final CSS Clipboard Regression Audit & Milestone Closure
=================================================================
Date: 2026-11-20
Base: HEAD a226b7d (BC-11.3, committed). BC-11.4 changes are uncommitted.


1. EXECUTIVE SUMMARY
--------------------
The audit exercised global and section-level Copy/Paste CSS together with
the other systems they touch:
- multi-selection, style locks, validation and Undo/Redo;
- layout CSS, Flow/Free;
- the element clipboard, keyboard and menus;
- complex values and images;
- Canvas, Preview, Export and Save/Reopen.

It found and fixed two genuine BC-11 issues:

R1 (Medium) — global Copy CSS copied groups the source no longer offers.
  captureStyleSnapshot ran without the "offered" filter, so a stale stored
  value the source's own Inspector hides travelled with Copy CSS and was
  pasted invisibly. Examples: a Flex item setting left over after the
  element moved out of a Flex row; Position on a Free child.
  Fix: global copyStyle uses the same { onlyOffered: true } rule BC-11.3
  section copy already used. Regression test added.

R2 (Low, UX) — inconsistent display names. The same group was named three
  ways:
  - the single-selection header said "Visual Effects";
  - the multi-selection header's menu said "Copy Filters CSS";
  - the notice said "Filters".
  Fix: the registry label is the one display name, using the
  single-selection Inspector's header names ("Visual Effects", "Display &
  Visibility", "Border Radius", "Box Shadow", "Media", "Content Layout",
  "Flex item", "Grid item", "SVG Fill & Stroke"). The section menu uses it
  in every mode. Internal group ids are unchanged; component test added.

No High or Critical defect was found. Every focused test passes:
- Vitest: 257 tests in 12 files;
- Chromium: 10 tests in 3 BC-11 specs;
- Firefox + WebKit: 6 tests.

Recommendation: CLOSE BC-11, pending ChatGPT's approval.

7. MULTI-SELECTION AND ATOMICITY
--------------------------------
Multi-selection:
- cross-container, cross-tag;
- a parent and child each once;
- no cap;
- the selection is unchanged (asserted).

Style lock on any destination: nothing changes, no history, and the lock
notice is shown (global and section).

Validation failures, each refused whole with no partial write:
- an invalid authored value (schema check before commit);
- a Free size that doesn't fit;
- a parent + child pair where the parent's new size would no longer
  contain the child (a new audit case: refused, containment wins);
- the project size limit (the save-limit guard).

Skipping is distinct from failure: an unsupported group is skipped (D5),
and the rest of the paste still applies in the same step (the audit test
pastes background + size while Content Layout is skipped).

Undo/Redo:
- one entry per paste (global or section);
- Undo restores each destination's own values; Redo reapplies;
- no-ops and copies add nothing;
- Mixed returns after Undo (Chromium: h2 40px vs p 20px → Paste
  Typography → 40 → Undo → "Mixed").

15. DEFECTS DISCOVERED AND CORRECTED
------------------------------------
R1 Medium, global copy of non-offered stale groups.
   - Reproduced: the clipboard held ["flexChild", "typography"].
   - Cause: copyStyle didn't filter by the source's own Inspector rules.
   - Fix: { onlyOffered: true } (one line).
   - Test: bc11Audit "repro" (now passes).
R2 Low, inconsistent group names.
   - Cause: the menu used each header's local label; the notices used
     terse registry labels.
   - Fix: registry labels = the Inspector's single-selection header names,
     and the menu uses the registry label.
   - Test: InspectorSectionCssMenu "one display name…". Three existing
     notice expectations were updated to the new names ("Content Layout",
     "Flex item"); the behaviour asserted is unchanged.
No other defects.

17. KNOWN NONBLOCKING LIMITATIONS (intentional)
-----------------------------------------------
- Flow↔Free structural conversion is excluded: skipped and named.
- Free-container bounds are the existing approximate one-shot bounds
  (stored size, else 400 × 300). An oversize is refused, never shrunk.
- SVG coverage is fill / stroke / stroke-width: complete for the current
  SVG section (section 5).
- Labels are now consistent (R2). The multi-selection headers themselves
  still read "Filters" / "Display" (BC-10.4 wording, not changed here); the
  menu and notices use the full names.
- No section-level keyboard shortcuts (menu-only, as allowed).
- No exact computed-appearance copying (D8).
- Class names are excluded: they are HTML attributes, not CSS declarations.
- Pasting onto Pagination links changes their look (their own CSS), never
  their current-page state.
