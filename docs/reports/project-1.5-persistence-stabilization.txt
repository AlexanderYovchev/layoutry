F. RECOVERY PERFORMANCE ANALYSIS
======================================================================================
Measured first: CPU profiles of a snapshot in the real Electron app (5,000 elements and
9.7 MB) showed TWO long tasks per snapshot:
  1) serialization's loader self-check (Zod ≈ 60 % of it) + TextEncoder for the hash;
  2) a full React re-render of every Canvas node, triggered by the recovery status change.
     Root cause: EditorApp passed a new options object to dnd-kit's useSensor on every render,
     giving dnd-kit new activators and a new internal context, which re-renders every
     draggable node. The same happened on every save step (operation, library, baseline).
Changes: (F1) constant sensor options + stable panel elements; (F2) snapshot preparation in a
Web Worker (same prepareRecoverySnapshot code; page fallback). Validation strength unchanged,
canonical format unchanged, generations/ordering still owned by the coordinator; stale worker
answers can't overtake (matched by id, written in the same queued task).
Result (identical harness, before = 5489ae3 build, two runs each):
  snapshot longest task: 5k 162–179 ms → none; 9.7 MB 175–186 ms → none; 20k 460–492 ms → none.
Not done: incremental hashing (the cost is validation, which can't be incremental without
weakening it).

S. LONG-RUN STABILITY (e2e/desktop/persistence-soak.spec.ts)
======================================================================================
Cycle: edit + snapshot + save in place; rename + Save As new file; open the first file;
outside change → conflict → Overwrite; every 4 cycles clean close + relaunch (must offer
nothing) and hard kill while unsaved + relaunch (must offer; Discard).
Run 1 (15 min): 398 cycles / 4,374 ops / 99 restarts / 99 kills. Failed its own listener guard:
window keydown listeners +1 per cycle across restarts. Investigated with per-listener
histograms: the Canvas resize hook registers one window keydown listener per resizable node,
and the soak's edit inserted a Container each cycle (saved, so the document grew). Not a leak;
the test was wrong. Soak edit changed to insert+delete (size-neutral).
Run 2 (15 min): 481 cycles / 5,289 ops / 120 clean restarts / 120 kills — PASSED. Heap after GC
10.4–11.1 MB; window listeners constant 35; main-process active handles: one PipeWrap only (no
file handles); no temp files and no recovery records after any cycle; never offered work after
a clean close; save 49 ms (first 5) → 27 ms (last 5).
Run 3 (5 min, final code after F11): 162 cycles / 1,778 ops / 40 / 40 — PASSED, same flat profile.
Not measured: timers (no reliable external counter; unit tests use controlled clocks), Web
Locks in Electron (desktop uses main-process sessions). IPC tokens: bounded by design (32 per
window) and released on every path (unit tests).

U. REMAINING RISKS
======================================================================================
- Edits in the last 2–30 s before a crash can be lost (by design).
- Native write race narrowed, not closed; power loss may keep the previous version; FAT/exFAT
  and network drives don't guarantee atomic replace.
- Real file-symlink test unverified on this machine.
- Headless Chromium can't crash a single tab; tab-level crash is simulated by abrupt close.
- Suspected Web Lock release lag after an abrupt tab close may delay a recovery offer (P3).
- Saves still serialize on the main thread (86–360 ms on very large projects, user-initiated).
- Opening/restoring very large projects is dominated by Canvas rendering (1.2 s at 5k elements,
  12 s at the node limit) — editor performance, outside persistence.
- One window keydown listener per resizable Canvas node (efficiency, not a leak; Canvas-owned).
- Retention logic duplicated in desktop/ and src/ (both tested).
- Recovery copies are local and unencrypted.
- Format 2 must define how the first save of a migrated native file is confirmed.
- Convention question for review: CLAUDE.md's file-placement table has no entry for feature
  `workers/`; this checkpoint added src/features/project/workers/. CLAUDE.md not changed.
