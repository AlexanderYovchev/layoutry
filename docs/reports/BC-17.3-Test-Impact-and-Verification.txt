3. CHANGED TESTS AND WHY
======================================================================

Unit, ~150 assertions in 17 files (canvas element tests, resize matrix,
DocumentNodeRenderer): they read inline `element.style`, which no longer
holds authored CSS. Converted to:
- getComputedStyle(element) after installing the real generated sheet —
  stronger: it proves the rule actually applies;
- generatedStyleOf(element) where the old assertion meant "Layoutry
  declares nothing / declares X" (e.g. `.style.width === ""`), because
  jsdom's computed style adds initial and UA values, and jsdom ranks a UA
  rule above an author :where() rule (an origin bug), which would have
  made default-vs-UA assertions tautological (`list-style-type: disc`)
  or wrong (`display`);
- Tailwind-class assertions (`toContain("max-w-prose")`, "h-40",
  "list-disc", "underline", "inline-block", "flex") → the equivalent
  declarations (65ch, 10rem, disc, underline, inline-block, flex).
canvasExportParity.test.tsx: compares effective declarations (sheet vs
export defaults + declarations), empty inline style, and the generated
class (Report 2 §4). Catalog case: time budget 20 s (jsdom cascade).
useEditorStore.persistence.test.ts: the store-field inventory now lists
liveGesture as reset by replaceDocument.
legacyProjectFiles.test.ts: the BC-17.2 test "exports exactly what the
same document exports without its styling-foundation data (none of it
renders yet)" had an expiring premise — BC-17.3 renders it. Replaced by:
the CSS differs and contains the hover rule, aria-disabled mapping,
counter content and counter-reset/increment, no data-ly-force, and the
markup is identical apart from generated classes.
EditorApp.test.tsx: two multi-round tests 15 s → 30 s (measured: 7.5 s /
4.7 s alone; with sheet insertion disabled they return to HEAD's 4.2 s /
2.4 s — jsdom's cascade, not the app).
e2e, 6 specs (bc13-final-audit, free-insertion-snapping,
free-interaction-lifecycle, bc05-final-regression,
inspector-computed-typography, inspector-reset): read the STORED
geometry/authored value through `el.style`; now through
__lyDeclaredStyle(el) (generated rules + live override; `{ authored:
true }` excludes default presentations, which is exactly what inline
style held). Assertions unchanged.

======================================================================
4. DEFECTS FOUND BY VERIFICATION (ALL FIXED)
======================================================================

D1 Commit left the pre-gesture geometry in the sheet when the document
   object did not change (the unchanged-subtree skip never revisited the
   ex-live node). Found by the hook integration test. Fixed: a gesture
   end forces one revisit; regression unit test added.
D2 StyleSheetHost rewrote all of a node's rules for any change (4
   mutations instead of 2). Fixed: per-order-key diff.
D3 Within an order key the host kept arrival order (cascade-harmless,
   but not the canonical order). Fixed: owners sorted by node id;
   randomized test proves installed == printed.
D4 Production: the <style> appended to <head> was missing in ~1 of 4
   loads (framework head reconciliation during hydration) → unstyled
   document. Fixed: DocumentCanvas renders the <style> (React owns it).
D5 Production: the document painted unstyled until hydration (~0.6 s;
   specs acting right after hydration saw 16px headings). Fixed: the
   first document's sheet is server-rendered as the <style>'s text
   (deterministic compiler, so hydration matches; no HTML escaping —
   verified in the built HTML); scope from useId. 16/16 loads styled
   from the first sample (was 18/24).
D6 Four components (Progress, TableRow, TableSection, Option) had lost
   their generated class in the mechanical conversion. Fixed; caught by
   the Progress computed-style tests.
