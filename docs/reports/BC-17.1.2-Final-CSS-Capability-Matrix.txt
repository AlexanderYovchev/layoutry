STATUS CODES
FULL      supported (authorable; Design, Preview and Export)
PARTIAL   supported with a named gap
NOT-EXP   implemented but not exposed for authoring
MISSING   missing implementation; a checkpoint is assigned
BROWSER   browser-restricted; included under O15 with a documented limit
          (combined as MISSING+BROWSER when also missing)
EXCLUDED  fails the O15 gate (Chromium only, or a single engine);
          documented, not built
BLOCKED   architecturally blocked by design (reason given)
N/A       not applicable (the CSS cannot apply; reason given)
OWNER-OUT outside BC-17 by an explicit owner decision (O8, O13)
OPEN      the path depends on an open owner decision (P-1…P-4)
UNVER     the classification needs a browser check at the assigned
          checkpoint

V3 browser-specific; targeted tests required

A2 LOGICAL PROPERTIES AND WRITING MODES (CORRECTED)
BC-17.1.1 classified these N/A. That was wrong: they are applicable CSS
regardless of whether Layoutry authors direction, and writing-mode IS a
visual styling property.
- writing-mode (horizontal-tb, vertical-rl, vertical-lr), text-orientation
  — MISSING — E (text-bearing, containers) — all — typography —
  Chromium/Gecko/WebKit — 17.7 — V2.
- Logical margin/padding (margin-inline/-block-start/-end…), logical
  sizes (inline-size, block-size, min/max), logical insets
  (inset-inline/-block…), logical borders and radii
  (border-inline-start…, border-start-start-radius…) — MISSING+OPEN —
  E — all — spacing, size, position, border, borderRadius — supported in
  all three engines.
  - Architecture note: a physical and a logical longhand for the same box
    side are TWO declarations for one owner. Authoring both creates an
    order-dependent conflict (the same lesson as
    feedback_css_shorthand_longhand_conflict). One representation per
    group per element is therefore required.
  - P-2 decides the model — 17.7 — V2.
- CSS direction / unicode-bidi — N/A by standard: CSS Writing Modes
  advises authors to use the HTML dir attribute, not the direction
  property. The dir attribute is document content/semantics (component
  properties → Accessibility), not CSS styling. Covered by P-2 option C.
- Interaction with physical properties: per P-2; the default
  recommendation is a per-group "Physical | Logical" representation,
  with lossless conversion for horizontal-tb LTR.
- Inspector usability: logical labels ("Inline start") shown only in
  Logical mode.

Internal targets versus real children:
- Real children of every composition remain nodes: selectable and
  styled as nodes. A role group styles a SET of real children from the
  component root. It never replaces per-child styling.
  - Ordering is global by rank (Report 1 §6.4): within a rank, the
    role-group rule comes before the child's own rule.
  - So a child's own rule of the same rank wins, and a higher-rank
    role-group state (e.g. current) wins over the child's base.
- Internal targets = pseudo-elements, native parts, custom-progress
  parts, structural targets, role groups and vector objects. None are
  document nodes.
