LAYOUTRY — BC-02.2.1: MUTED-ONLY AUTOPLAY POLICY
=================================================
Date: 2026-11-05
Type: Small corrective fix + targeted regression tests
Baseline: HEAD 61fa9de (BC-02.2, usePreviewMediaPlayback).
Status: Implemented and tested. Awaiting QA review. Not committed.


1. SUMMARY
----------
Product decision: Layoutry starts playback by itself only for media
authored as BOTH autoplay and muted.

Before this change:
- Preview called play() on every autoplay element. Because entering
  Preview is a click, Chromium and Electron allowed unmuted media to start
  with sound. This was measured, not assumed: with the old rule restored,
  the unmuted test video was playing in both.
- Export wrote `autoplay` for unmuted media and left it to the browser to
  block it.

Now:
- Preview: unmuted autoplay media gets no play() call and no native
  `autoplay` attribute.
- Export: `autoplay` is written only for muted media. When an unmuted
  autoplay is left out, the export shows a warning.
- The authored `autoplay` and `muted` fields are never changed. Nothing is
  muted to make it play, and manual playback, pause, seek, volume, loop and
  controls all still work.
- B2 (muted autoplay starts) and B3 (everything stops on Exit Preview) are
  still fixed.

No schema change, no new permission, no Electron or CSP change.

3. IMPLEMENTATION DECISIONS
---------------------------
D1 One rule, shared. getEffectiveAutoplay lives in editor/types/video.ts,
   the owner of media field semantics, so Preview and Export cannot drift
   apart. The document keeps the authored values; only the rendered and
   exported attribute is derived.

D2 Two gates in Preview.
   (a) The effective rule decides the native attribute and whether the
       hook may play.
   (b) The hook also checks the element's live `muted` property. A user
       can unmute muted media with its controls during Preview. React
       never re-syncs `muted` unless the authored value changes, so on
       the next Preview entry that element is unmuted, and the hook does
       not start it with sound. Each gate has its own failing test
       (section 5).

D3 No native autoplay attribute for unmuted media in Preview, so an
   unmuted element first mounted during Preview (inside something an
   interaction shows) cannot start through the attribute either.

D4 Export drops the attribute and does not rely on browser blocking. The
   brief says not to emit an effective autoplay instruction for unmuted
   media. `muted` is still exported only when authored, so nothing is
   muted for the user.

D5 Export warning, severity "warning". exportDiagnostic.ts defines
   warning as "something authored was dropped", which is what happens
   here. Message: "Autoplay was left out because the media is not muted.
   Layoutry only autoplays muted media; the controls still start it."
   Without it the authored setting would vanish from the output silently.
   It does not block export.

D6 Not changed: the Inspector's Autoplay and Muted toggles, which still
   save what the user sets. An Inspector hint ("autoplay requires
   muted") would be a UI change outside this brief; it is a suggested
   follow-up.


4. POLICY MATRIX (Preview and Export, measured)
-----------------------------------------------
autoplay  muted   Preview                Export
on        on      starts (C F E)         autoplay + muted exported;
                                         plays on load (C F)
on        off     paused at 0; not muted paused at 0; no autoplay
                  (C F E)                attribute; warning (C F)
off       on      paused (U)             no autoplay (U)
off       off     paused (U C F E)       no autoplay, paused (U C F)
C Chromium, F Firefox, E Electron, U Vitest.

Manual playback of unmuted autoplay media: started after a real click,
it plays, keeps its sound (muted === false), and stops on Exit Preview
(C F). On the exported page it also starts by hand (C F).
Loop and controls keep their authored values in Preview and Export
(the exported attributes are checked for v-auto, a-auto, v-sound and
a-sound).


5. TEST EVIDENCE
----------------
Unit tests (Vitest):
- getEffectiveAutoplay: 6 combinations.
- Hook (real Canvas, real store, play/pause spied):
    starts only muted + autoplay; unmuted autoplay and no-autoplay media

7. REMAINING LIMITATIONS
------------------------
- WebKit: NOT VERIFIED. Playwright's Windows WebKit build loads no media
  at all (readyState stays 0 even on a plain page outside Layoutry;
  BC-02.2 section 12). This is the test platform, not a Layoutry defect.
- MP4/H.264: NOT VERIFIED (no H.264 in Playwright's Chromium). The policy
  does not depend on the codec.
- Muted autoplay still depends on the browser. It is allowed by default
  in every major browser, but user or enterprise settings can block it.
  A rejected play() is ignored, and the controls still work.
- Exported projects that relied on unmuted autoplay change behavior: the
  attribute is no longer written, and the warning says so. Browsers
  blocked those in most cases anyway.
- The Inspector does not yet tell the user that autoplay needs mute
  (D6, follow-up).

9. RECOMMENDATION
-----------------
CLOSE BC-02.2.1 (and with it BC-02.2) after QA.
- Muted autoplay works when permitted: Chromium, Firefox, Electron.
- Layoutry no longer starts unmuted autoplay in Preview or Export. The old
  rule demonstrably played it in Chromium and Electron; the new tests fail
  on it.
- Manual playback works in Preview and on the exported page.
- B3 cleanup still holds (all media paused on exit, every session).
- No schema change, no new permission, no unrelated export change; one
  new export warning code.
Suggested follow-up (not in this brief): an Inspector hint next to
Autoplay saying it needs Muted.
