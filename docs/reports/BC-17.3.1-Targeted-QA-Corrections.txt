3. QA-1 — CROSS-SURFACE CASCADE ORDERING
======================================================================

Analysis. All generated rules have equal specificity, so order decides.
Inside one order key, Design/Preview order owners by node id, Export by
document order. Overlaps of DIFFERENT owners on one element under one key:
- role groups (tier 0) vs the member's own rules (tier 1): different keys
  — already safe;
- structural chains were tier 1 — the SAME key as the target element's own
  rules (e.g. a container's group.first vs its first child's base
  background, a table's table.cell vs a cell's background): order then
  differed between surfaces;
- two different tier-0 owners on one element: not reachable with the
  current targets (role groups and group.first/list.first reach direct
  children only; table chains have no competing ancestor owner), but not
  guaranteed for later targets.

Fixtures (src/features/export/utils/crossSurfaceCascadeOrder.test.tsx):
the Preview Canvas (real components + real compiled sheet) and the
exported page (real printer, real HTML) in jsdom; each element's winning
declaration compared, with ids chosen so id order ≠ document order:
  1 container group.first + first child's own background (owner first)
  2 the same with ids reversed (owner sorts after its child)
  3 table.cell vs a cell's own background, and an untouched cell
  4 Pagination role group + the root's list.first + a member's own background
Before the fix: 3 of 4 failed — fixture 1 rendered BLUE in Preview and RED
in Export (a real cross-surface discrepancy); 2–3 agreed but let the
container's structural rule beat the element's own styling, contrary to
the role-group contract (fixture 4, a role group, already passed).

Fix:
- compileNodeStyle.ts: structural chains take tier 0 (they are an owner
  styling its descendants, exactly like role groups), so the target's own
  rules of the same bucket always come later and win, on every surface.
- Export printing: inside a tier-0 key, rules of different owners follow
  the Canvas order (owner node id, then the owner's own order); tier-1
  keys keep document order (own rules only ever reach their owner). The
  export IR records each rule's owner (ExportStyleRule { sourceNodeId,
  rule }). Class identity and the stylesheet host are unchanged.
After: 4/4 pass; existing parity (unit 8/8, Chromium export-visual-parity
and preview-export-parity) pass.

4. QA-2 — GESTURE CANCELLATION (FREE RESIZE, GRADIENT STOP)
======================================================================

Added to e2e/stylesheet-gesture-trace.spec.ts (existing tracer reused):
"Free resize, Escape …" and "gradient stop drag, Escape …". Each test
first makes a committed edit and undoes it (so Redo is available), saves
the project, then performs the traced gesture and presses Escape. Checks:
- exact original geometry / background-image (the ACTUAL computed
  background-image per frame and the declared value after);
- zero document-sheet mutations for the whole gesture, cancel included;
- override removed, no inline style left, declared value == original;
- project status stays "saved" (document identity == persisted);
- IndexedDB document unchanged; the real exporter's CSS unchanged;
- no history entry: Redo still restores the earlier edit; one Undo
  returns to the original.

Results before any fix: Free resize Escape PASSED every check (missing
verification only). Gradient stop Escape FAILED: after Escape and release
the stop still painted the live override — the drag and its transaction
were left open (the stop track handled only pointer-up; Escape and
pointercancel were not handled; cancelTransaction never restored the live
value). Confirmed defect.

Fix:
- useEditorStore.restoreLiveBackgrounds(): rolls back every node the open
  live gesture wrote a background-image slice for (multi-selection
  fan-out included) from the transaction snapshot; an exact rollback
  reuses the snapshot's document object (nothing reads as unsaved), like
  restoreFreeLayoutsLive; other edits made meanwhile are kept.
- InspectorGradientStopTrack: Escape (captured, only while dragging),
  pointercancel, lost pointer capture and unmount mid-drag call
  onDragCancel; the release after a cancel does nothing.
- InspectorGradientSection: onDragCancel = restoreLiveBackgrounds() +
  cancelTransaction().

Traces (after the fix):

======================================================================

Document: 200 unrelated paragraphs; a section resetting counter X; two
headings incrementing X with ::before content counter(X); one element
incrementing counter Y. Edit: rename X (its CSS identifier changes; Y's
does not) — as a store edit does: new root, every element keeps identity.

                                   before fix   after fix
  traversal (nodes visited)           205          205
  cache lookups                       205          205
  nodes recompiled                      5            3
  nodes whose rules changed             3            3
  stylesheet mutations                 10           10
(5 before = the 3 dependants + the root, whose object changed only through
styleAssets, + the Y-only element.) Adding a definition nothing references:
before 5 recompiled; after 0 recompiled, and only the root plus one lookup
per direct child (203), no subtree descended.

Fix (documentStyleCompiler.ts): a node's own key holds the identifiers of
exactly the counters it references (was a global epoch); styleAssets is a
non-style input of the root; a definitions change walks the tree only when
a cached node references a counter whose identifier changed. Identifier
resolution is unchanged and deterministic. Randomized incremental == full
(2 surfaces × 8 seeds × 40 edits, counter renames included) still passes;
new counterInvalidation.test.ts asserts the numbers above, the collision-
suffix shift case and full-rebuild equality.
