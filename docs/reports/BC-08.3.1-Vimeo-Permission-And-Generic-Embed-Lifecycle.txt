1. EXECUTIVE SUMMARY
--------------------
Both approved decisions are implemented and verified.

A. Vimeo
- Root cause verified again before any change, in headed Microsoft Edge
  (the one available browser that can decode Vimeo's streams). The only
  missing piece was the Permissions-Policy feature `encrypted-media`.
  - With it alone, and the sandbox unchanged, Vimeo plays like its
    official embed.
  - Without it, it never plays.
- Validated Vimeo Video Embeds now get
  allow="fullscreen; encrypted-media" in browsers, and
  allow="encrypted-media" in the desktop Preview, where fullscreen stays
  off until BC-08.4.
- The permission comes only from the re-validated provider identity in
  the shared configuration, so Preview and every export format are
  identical.
- No other provider, generic Embed, invalid or spoofed source gets it
  (unit, browser and export tests).
- Live, in Edge: Vimeo muted autoplay plays in Preview (11.6 s) and on the
  exported page (12.6 s). Vimeo is now marked verified.
- Playwright's bundled Chromium, Firefox and WebKit cannot play Vimeo with
  Vimeo's own official embed either (codec/DRM/media limits of those
  builds), so they cannot verify Vimeo either way.

B. Generic Embed lifecycle
- Generic Embeds now share the Video Embed lifecycle rule
  (usePreviewFrameShown).
- In Preview the frame exists only while the Embed and every ancestor are
  shown. Hiding it, hiding an ancestor, or leaving Preview removes the
  framed document.
- Entering and leaving Preview each create a fresh frame, so nothing from
  a Preview session keeps running in Design.
- Exported pages apply the same rule through the export runtime. Frames
  that stay shown are never touched.
- Source, sandbox, markup, document and history are unchanged.

2. ROOT-CAUSE VERIFICATION
--------------------------
Method:
- A temporary probe (deleted afterwards) loaded the same Vimeo URL
  (https://player.vimeo.com/video/76979871?dnt=1&autoplay=0) from a real
  loopback http origin, in four embeddings.
- After 6 s the probe recorded whether the EME API exists inside the
  frame. It then clicked the player (manual playback) and read the
  <video>'s currentTime 8 s later.

  Embedding (sandbox = BC-02.3 tokens unless stated)   Edge (headed)       Pw-Chromium   Pw-Firefox   Pw-WebKit
  ---------------------------------------------------  ------------------  ------------  -----------  ---------
  allow="fullscreen"            (BC-08.3 markup)        paused, 0.0 s       0.0 s         0.0 s        0.0 s
  allow="fullscreen; encrypted-media"                   PLAYING, 2.5 s      0.0 s         0.0 s        0.0 s
  allow="encrypted-media"                               PLAYING, 5.7 s      0.0 s         0.0 s        0.0 s
  Vimeo official embed, NO sandbox
    (allow="autoplay; fullscreen; picture-in-picture;
     clipboard-write; encrypted-media; web-share")      PLAYING, 5.0 s      0.0 s         0.0 s        0.0 s

Conclusions:
- `encrypted-media` is necessary: without it Vimeo never plays in Edge.
- It is sufficient: with it alone Vimeo plays.
- The sandbox can stay exactly as it is: the sandboxed variant plays like
  the unsandboxed official embed.
- No other feature is needed: not autoplay delegation, picture-in-picture,
  clipboard or web-share.
- The bundled Playwright engines fail even with Vimeo's official embed.
  That is an environment limit (no H.264/Widevine in Playwright's
  Chromium, Windows Firefox/WebKit builds without the needed media
  support; WebKit has no EME API at all), not Layoutry.
  - Live, Playwright's Chromium even shows Vimeo's "Rights issue — trouble
    authorizing playback".
- BC-08.3's earlier observation was that, without encrypted-media, Vimeo
  shows "Unable to play video. Please try again in a supported browser."
- Remaining provider-side restrictions: owner domain whitelisting,
  private videos, Rights issues. These are shown by Vimeo itself.


3. VIMEO PERMISSION IMPLEMENTATION
----------------------------------
src/lib/videoEmbed/videoEmbedProviders.ts:
- Each provider has `permissions: readonly VideoEmbedPermission[]`, where
  VideoEmbedPermission = "encrypted-media".
- Vimeo: ["encrypted-media"]. YouTube, Loom and Wistia: [].
- Vimeo playback is now { status: "verified" }.
- The "blocked" playback status and its export/Inspector/placeholder paths
  were removed, since no provider needs them now. The diagnostic
  "video-embed-blocked" is gone too.

src/lib/videoEmbed/videoEmbedPlayerConfig.ts, allowAttribute(provider,
fullscreenAllowed):
  ["fullscreen" if allowed and capable] + provider.permissions, joined
  with "; "; undefined when empty.

All the brief's conditions hold:
- the element is a Video Embed (isVideoEmbedNode, BC-08.2 identity);
- the provider comes from the central parser (readVideoEmbedSource
  re-parses the stored src on every render and export);
- the destination is rebuilt on the exact embed host player.vimeo.com and
  re-checked (https, no port, no credentials);
- the attribute is produced only by this pipeline.
Never from:
- substrings;
- an unvalidated persisted value (no document field holds permissions;
  the schema refuses an `allow` field);
- a generic Embed (its iframe path never sets allow);
- user input.


4. EXACT PERMISSIONS POLICY CHANGES
-----------------------------------
                         Browser Preview / every export      Desktop Preview
  ---------------------  ----------------------------------  ---------------------
  Vimeo Video Embed      fullscreen; encrypted-media         encrypted-media
  YouTube/Loom/Wistia    fullscreen                          (no allow)
  Generic Embed          (no allow)                          (no allow)

The allowlist is the attribute's default, 'src': the frame's own origin,
which is always the validated https://player.vimeo.com. An explicit
origin list was not used: it adds nothing over 'src' and has narrower
parser support.

Not granted, anywhere: camera, microphone, geolocation, clipboard,
payment, display-capture, autoplay, picture-in-picture, web-share, or
any other feature.

8. GENERIC EMBED LIFECYCLE IMPLEMENTATION
-----------------------------------------
- Shared rule: src/features/canvas/hooks/usePreviewFrameShown.ts.
  - shown = isPreview AND NOT RuntimeHiddenContext (the element or any
    ancestor hidden by an interaction) AND NOT isNodeAuthoredHidden
    (Display none / Visibility hidden on itself or an ancestor).
  - A pure derivation: no effects, timers or listeners, so nothing can
    fire late and re-create a removed frame. Idempotent by construction.
- VideoEmbedFrame (Video Embeds) now uses the hook instead of its own copy
  of the rule.
- IframeElement (generic Embeds):
  - Design: the live iframe, as BC-02.3 established, keyed
    "<sandbox>|design".
  - Preview: an iframe only while the hook says shown, keyed
    "<sandbox>|preview".
- Mode keys guarantee a fresh document on every entry and exit.
  Source, sandbox and attributes are unchanged.
- Project switching, deletion and editor unmount unmount the component;
  duplicates are independent nodes.
- Approved behaviour change: BC-02.3's test "repeated Preview sessions
  keep the same iframe" now asserts the approved behaviour:
  - a fresh frame on each entry and exit;
  - the frame count never grows;
  - the same sandbox;
  - 11 loads for 5 sessions (1 + 2 per session);
  - Undo still disabled.

12. EXPORTED WEBSITE BEHAVIOR
-----------------------------
- Markup is unchanged for generic Embeds (no new attribute).
- The runtime (present whenever the page has interactions, an open-at-load
  dialog or a Video Embed player) manages every <iframe>, since every
  iframe on an exported page is a Layoutry Embed:
  - at load, a hidden or unrendered frame is removed;
  - a shown frame whose markup is already right is kept as-is;
  - on every visibility change, frames no longer shown are removed, and
    frames newly shown are recreated fresh (a generic one from its own src).
- A frame that stays shown is never touched:
  - jsdom: the same element after 6 toggles of another target;
  - browser: a property marker survives the whole exported-page test.
- Pages with no runtime (purely static) keep their frames exactly as
  before.
- No editor runtime dependency.
- No polling or MutationObserver: visibility on exported pages changes
  only through the runtime's own setVisible, and authored CSS is static.
  An observer would add cost with no event to observe.

26. REMAINING LIMITATIONS
-------------------------
- Vimeo is verified in Edge. Real Firefox and Safari are not verified
  (Playwright's builds cannot play Vimeo even via its official embed).
- Vimeo and YouTube in the desktop app: pending BC-08.4 (Referer,
  permissions).

  static page has no visibility changes to react to.
- Provider rules (owner restrictions, Rights issues, Referer) still apply.
