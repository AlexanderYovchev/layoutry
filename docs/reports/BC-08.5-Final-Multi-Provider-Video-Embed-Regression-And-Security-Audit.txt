1. EXECUTIVE SUMMARY
--------------------
BC-08 (Video Embed: YouTube, Vimeo, Loom, Wistia) was re-tested end to
end: Inspector, Canvas, Preview, exported pages, the desktop app,
persistence, undo/redo, legacy files, responsive layout, accessibility,
performance and security.

One real defect was found and fixed (D-A, Medium):
- On EXPORTED pages, a player or generic Embed under an authored
  Visibility: hidden (on itself or inherited from an ancestor) stayed
  loaded. A muted autoplay player could play invisibly; a generic Embed
  could play sound nobody could see or stop.
- Preview already removed it (isNodeAuthoredHidden), so the two
  disagreed.
- Fix: the export runtime's "shown" test now also requires the computed
  visibility to be neither hidden nor collapse. A descendant's own
  Visibility: visible still wins, exactly as in Preview.
- Regression test added. Nine runtime lines changed; nothing else in the
  product changed behavior.

One status change, from new evidence:
- Loom playback: "unverified" -> "verified". Loom's own public video
  played (muted autoplay) live in Chromium, Firefox, Edge and the desktop
  app, in Preview and on exported pages. The Inspector's "hasn't been
  confirmed" note for Loom is gone. This closes carried item D5.

No other defects were found. Specifically re-verified:
- The parser refuses redirect/wrapper links and huge input fast (new
  tests).
- The sandbox, allow and Referer policies are unchanged.
- Electron authorization survives 89 Preview sessions (277
  registrations, over the 256 cap: proof that nothing leaks), 11
  fullscreen grants and 6 project switches, with no listener, frame or
  window growth.
- The browser stress run: 25 Preview sessions, 60 show/hide
  transitions and 10 byte-identical ZIP exports; nothing accumulates.

Remaining limitations are environmental or by design and unchanged:
- Vimeo in the desktop app: no Widevine (approved: not integrated).
- YouTube from a file:// page: Error 153, no Referer. Documented in the
  Inspector and the export dialog's note.
- Playwright's own engines can't decode some providers' streams;
  Edge (a real Chrome-family browser) is the reference.
- E1 (Electron fullscreen race under ~50 ms): carried, Low.

Validation: - Vitest: 6011 passed, 1 skipped. On the first run, one pre-existing
  load-timeout flake unrelated to BC-08 (section 33). A full re-run was
  clean.
- Chromium full suite: 280 passed, 3 skipped (opt-in live).
- Firefox + WebKit targeted: 111/112. The one failure was a WebKit
  timeout under parallel load; the test passed 3/3 alone (section 36).
- Electron full suite: 87 passed, 3 skipped. Security specs: 35/35 over
  5 repeats.
- typecheck, desktop typecheck, lint, web build and desktop build:
  clean.

Recommendation: CLOSE BC-08 after QA review (section 40).

---------------------------------

  live playback not possible in this environment.
BLOCKED = cannot play here; cause named.
NOT TESTED = could not be run here; reason named.

                      YouTube     Vimeo        Loom         Wistia
Chromium (Playwright) VERIFIED    BLOCKED(a)   VERIFIED     VERIFIED
Firefox (Playwright)  VERIFIED    BLOCKED(a)   VERIFIED     VERIFIED

  (http://127.0.0.1)
file:// export        BLOCKED(f)  VERIFIED(e)  VERIFIED(g)  VERIFIED(g)
  (Edge / Chromium)
file:// export        NOT TESTED(h) for all four
  (Firefox)

(a) Playwright's Chromium build has no H.264, and its Windows Firefox and
    WebKit builds cannot decode Vimeo's streams. Vimeo's OWN embed code
    fails the same way there, so this is the test browser, not Layoutry.
    Edge plays it (7.4 s Preview, 14.7 s export).
(b) Playwright's Windows WebKit: the Loom player loads, its video stays
    at t ~ 0.1 s and never progresses. Its media stack is known to be
    weak on Windows (YouTube and Wistia use other paths and play).
(c) Electron ships no Widevine DRM component; Vimeo's own unsandboxed
    embed fails identically. Approved limitation, shown in the
    Inspector.
(d) No HTTPS host was available to this run. The local http server is
    the closest reproducible stand-in: a real http(s) origin with a
    Referer. Markup, policy and runtime are origin-independent and
    covered by the deterministic export tests.
(e) Edge only, for the reason in (a).
(f) YouTube requires a Referer; a file:// page sends none, so YouTube
    answers Error 153. This is YouTube's rule; the Inspector's YouTube
    limitation and the export's `video-embed-needs-website` note say so.
(g) Edge and Playwright Chromium.
(h) Playwright's Firefox driver doesn't expose frames of a file:// page,
    so the player's state can't be observed.

Live timings to first progress (muted autoplay): YouTube ~7 s, Wistia
~8-15 s, Loom ~30 s in Chromium (46 s in Electron, a slow first CDN
fetch), Vimeo (Edge) 7.4 s.

12. AUTOPLAY / REDUCED MOTION
-----------------------------
- Autoplay is requested only when Autoplay AND Muted are on and the
  provider supports it, and never when the viewer asks for reduced
  motion. Unit-tested per provider; browser-tested (emulateMedia) in
  Preview and on exported pages; desktop-tested (emulateMedia, because
  Electron ignores --force-prefers-reduced-motion).
- Muted is never switched on implicitly.


13. VISIBILITY LIFECYCLE
------------------------
A player exists only while it is shown. "Shown" now means the same thing
in Preview and on exported pages:
- not inside a hidden interaction target or a closed dialog;
- rendered (no display: none on it or an ancestor);
- NEW on export (D-A): computed visibility is neither hidden nor
  collapse. An ancestor's Visibility: hidden counts; a descendant's own
  Visibility: visible overrides it, as in Preview.
When hidden, the frame is removed; when shown again, a fresh frame is
created. A frame that stays shown is never touched.

18. REVOCATION
--------------
Authorization ends with the player:
- hide (the frame is removed; window leaves fullscreen);
- Preview exit (frames removed, window restored, nothing playing);
- project switch (players removed; old names refused);
- window reload/crash/close (whole window entry cleared).
Stress proof: registrations are capped at 256 per window and a failed
registration leaves the player without a src (fail closed). After 277
registrations every player still loaded, so every unmount unregistered.

27. SECURITY FINDINGS
---------------------
Audited, with the result:
- URL parsing (src/lib/videoEmbed/): only https on exact hosts; IDs by
  strict per-provider patterns; no redirect or wrapper following (NEW
  tests: youtube /redirect and /attribution_link, google.com/url,
  path traversal "../..", a URL smuggled in v=); huge input refused fast
  (NEW test). No finding.
- Stored src is re-parsed at render and export time; nothing trusts the
  stored string. No finding.
- Iframe policy: fixed sandbox; per-provider allow from the registry
  only; strict-origin-when-cross-origin referrer policy. No finding.
- Export runtime: builds frames from data-ly-video-src only on
  elements it emitted; generic Embeds are re-created with their own
  attributes. D-A (visibility) was a privacy/consent issue, fixed.
- Desktop: frame identity bound to the real frame tree (direct child,
  registered name, exact origin); Referer only on that frame's own
  document request; one fullscreen exception; checks stay denied; IPC
  sender validation; registry cap. No finding; stress confirms no
  leak.
- CSP frame-src http: https: unchanged (authored iframes, pre-BC-08).
- Electron hardening invariants (contextIsolation, sandbox,
  nodeIntegration off, no webview): unchanged, green.
No Critical or High finding.
