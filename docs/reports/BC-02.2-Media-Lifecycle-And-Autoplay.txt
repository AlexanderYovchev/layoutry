LAYOUTRY — BC-02.2: MEDIA LIFECYCLE & AUTOPLAY STABILIZATION
==============================================================
Date: 2026-11-05
Type: High-severity bug fix + integration tests
Baseline: HEAD 019d6ca (BC-01.6) plus the uncommitted BC-02.1 report.
Status: Implemented and tested. Awaiting QA review. Not committed.

Classification used below:
  CONFIRMED     measured in a real browser or Electron, or a direct code fact
  NOT VERIFIED  not checked, with the reason


1. EXECUTIVE SUMMARY
--------------------
B2 (muted autoplay never starts in Preview) and B3 (media keeps playing
after Exit Preview) share one root cause: the Canvas renders a single
native <video>/<audio> element for both Design and Preview, and entering
or leaving Preview changed only its `autoplay` attribute. Nothing ever
started or stopped playback.

The fix is one small canvas hook, usePreviewMediaPlayback, used by
VideoElement and AudioElement. When Preview starts it calls play() once
on media with autoplay enabled. When Preview ends, or the element
unmounts, it calls pause(). No document, store, export, schema or
Electron change was made.

Both defects are fixed and covered by tests that fail without the fix:
  - Vitest: 9 of the 13 original hook tests fail with the hook disabled.
  - Chromium: 5 of 7 browser tests fail with the hook disabled (B2 and B3
    each reproduced on their own).
  - Electron: the desktop test fails with the hook disabled (B2).
With the fix, every test passes in Chromium, Firefox and Electron.
WebKit could not be verified: Playwright's Windows WebKit build loads no
media at all, even on a plain page outside Layoutry.

Recommendation: CLOSE BC-02.2 (section 16), with one open product decision
about unmuted autoplay (section 14).


2. ROOT CAUSE OF B2 — MUTED AUTOPLAY DOES NOT START
---------------------------------------------------
CONFIRMED (code fact + browser).
- VideoElement/AudioElement render `autoPlay={isPreview && !!node.autoplay}`.
  The element mounts and loads in Design with no autoplay attribute.
- Enter Preview is a store change (editorMode "design" -> "preview"). React
  re-renders the SAME element and only adds the attribute. Nothing remounts.
- Chromium only acts on autoplay while the element is loading. An element
  that has already loaded ignores an autoplay attribute added later
  (reproduced on a plain page in BC-02.1). Firefox does start it, which is
  why B2 was Chromium/Electron only.
- Not a policy or muting problem: `muted` is committed as a property
  before any attempt, and a muted video is always allowed to autoplay.
  A video first mounted during Preview (for example, inside something
  shown by an interaction) did autoplay, because it loads with the
  attribute already set.

Reproduction (before the fix, Chromium, real app):
  1. Import a project with a video: autoplay + muted + loop, local WebM.
  2. Wait until it has loaded in Design (readyState >= 3).
  3. Click Enter Preview.
  Result: paused === true, currentTime stays 0. Test failure seen:
  "Error: v-auto should be playing" (preview-media-lifecycle.spec.ts, and
  e2e/desktop/preview-media.spec.ts in Electron).


3. ROOT CAUSE OF B3 — MEDIA KEEPS PLAYING AFTER PREVIEW
-------------------------------------------------------
CONFIRMED (code fact + browser).
- Exit Preview (exitPreview, and replaceDocument when a project is opened
  or created) only sets editorMode back to "design". The same element stays
  mounted, and removing the autoplay attribute does not pause anything.
- In Design, MediaInteractionShield covers the element again, so the
  native controls that could pause it can no longer be reached.

Reproduction (before the fix, Chromium, real app):
  1. Enter Preview; start every video and audio (the test calls play()
     after a real click, the same as using the native Play control).
  2. Click Exit Preview.
  Result: paused === false and currentTime keeps advancing in Design.
  Test failure seen: "Error: v-auto should be paused".

5. IMPLEMENTATION DETAILS
-------------------------
usePreviewMediaPlayback(mediaRef, { isPreview, autoplay }) is one
useEffect with deps [mediaRef, isPreview, autoplay]:

  if (!media || !isPreview) return;          // Design: do nothing
  if (autoplay) Promise.resolve(media.play()).catch(() => {});
  return () => media.pause();                // on exit or unmount

- play() runs only when Preview starts (or autoplay is switched on while
  in Preview). It does not run on unrelated renders, selection changes or
  store updates (unit-tested).
- The returned promise is always caught. A rejection (NotAllowedError
  from autoplay policy, or AbortError when a pause interrupts a pending
  play) is ignored. The user can still start the media from the controls.
- muted is never written by the hook. React commits the `muted` property
  before effects run, so a muted video is muted when play() is called
  (unit-tested by recording `this.muted` inside play()).
- Media without autoplay is never played by the hook.
- The `autoPlay={isPreview && ...}` attribute is unchanged. It still
  covers media first mounted during Preview and a source replaced during
  Preview.
- Why a hook and not a remount: a keyed remount on mode change would also
  restart loading every video, flash posters, and lose the playback
  position the brief asks to keep. The hook changes nothing that renders.


6. MEDIA LIFECYCLE BEHAVIOR (as implemented)
--------------------------------------------
Entering Preview   autoplay media: play() once; the browser's policy
                   decides. Other media stays paused.
During Preview     native controls work (the shield is gone, as before).
                   Playback state is runtime only.
Leaving Preview    every mounted video and audio is paused, autoplay or
                   not. Not rewound. Nothing written to the project.
Reopening Preview  autoplay media plays again from where it was paused.
                   Other media stays paused at its position.

Edge cases (U = Vitest, C = Chromium, F = Firefox, E = Electron):
  1  first Preview entry                    U C F E
  2  leaving Preview                        U C F E
  3  repeated Preview sessions              U (3x) C (3x) F (3x) E (2x)
  4  switching selection in Preview         U (no extra play())
  5  editing media properties               Design: hook does nothing
                                            (deps change, isPreview false).
                                            Preview: autoplay switched on
                                            plays once; switched off pauses.
  6  replacing the source in Preview        U: same element, src updated,
                                            no second play(); the native
                                            autoplay attribute starts it.
  7  deleting a media node in Preview       U: pause() on unmount
  8  deleting its parent                    U: nested media paused
  9  opening another project                U: replaceDocument resets the
 10  creating a new project                    mode and the old media is
                                               paused (both use
                                               replaceDocument)
 11  closing the project                    same path as 9/10
 12  navigating away / unmounting editor    U: pause() on unmount. The
                                            browser also stops media when
                                            the page unloads.
 13  switching modes                        only Design/Preview exist;
                                            covered by 1-3
 14  unmounting the editor                  U
 15  several media at once                  U C F E (6 elements)
  -  media hidden by an interaction         C F: Preview unmounts hidden
                                            nodes; after Exit Preview the
                                            remounted element is paused.
  Cases 5-8 during Preview are reachable only through the store, because
  Preview disables the Inspector and the editing shortcuts. They are
  tested at the store level as a safeguard. In Design the same edits are
  ordinary document edits, and the hook does nothing.
  -  Preview hidden but mounted             does not happen: Preview is a
                                            mode of the one Canvas, not a
                                            separate mounted view.

9. SECURITY IMPLICATIONS
------------------------
- No new Node.js exposure, IPC, permission, protocol privilege or CSP
  change. The fix runs only in the renderer, on elements it already owns.
- No autoplay policy bypass. The hook calls the standard play() and
  accepts a rejection. It never unmutes and never retries.
- Unmuted autoplay: see section 14. play() runs right after the user
  clicks Enter Preview, so the browser may allow sound that an exported
  page opened cold would block. That is the browser's own rule for a user
  gesture, not a bypass, but it is a parity difference.
- Test-only: copyApp now accepts binary files. It only writes into a
  temporary copy and never touches the real build.


10. PERFORMANCE AND CLEANUP
---------------------------
- No event listeners, timers, intervals or retry loops were added.
- The effect re-runs only when Preview starts or ends, or when that
  element's autoplay flag changes. Typing, selection, and other store
  updates do not run it (unit-tested: play() count unchanged).
- No DOM queries: each element uses its own ref. The effect captures the
  element for its cleanup, and nothing keeps it after unmount.
- Every play() promise is caught, so there are no unhandled rejections
  (unit-tested with process "unhandledRejection").

14. KNOWN LIMITATIONS
---------------------
- Unmuted autoplay (open decision). The hook calls play() for every
  autoplay-enabled element. A muted one always plays. An unmuted one plays
  only if the browser allows it. Because play() runs right after the Enter
  Preview click, Chromium usually allows it, while an exported page opened
  without a click would usually block it. If Preview should copy the
  exported page's cold-load behavior, the alternative is one line: call
  play() only when the element is muted. Not changed without a decision.
- Autoplay is never guaranteed. It is up to the browser and its settings.
- Playback position stays when the same element is reused. It is lost
  when the element remounts (hidden by an interaction, deleted and undone,
  or a project reopened). This matches the brief.
- Switching autoplay off for an element during Preview would pause it.
  This can't happen from the UI: Preview replaces the Inspector with a
  placeholder and ignores the editing shortcuts (Undo/Redo/Delete/...).
- WebKit and MP4 not verified (section 12).
