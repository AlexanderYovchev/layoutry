======================================================================
1. STRATEGY MEASUREMENT (A/B/C) — e2e/perf/stylesheet-strategies.spec.ts
======================================================================

Fixture: 1,001 nodes, 2,001 rules. A = rewrite one text sheet;
B = CSSOM insertRule/deleteRule on one sheet; C = one <style> per node.
Median ms (Chromium shows median/p95 where measured):

                      install   1-node edit   10-node edit   insert   delete   reparent
  Chromium  A           4.0       12.3           75.7          15.0     16.4      2.1
            B          23.3        0.8            1.2           2.2      2.5      2.7
            C           7.8        0.7            5.3           1.7      1.7      1.1
  Firefox   A          14         27            159
            B          34         10             11
            C          14         11             16
  WebKit    A          11         32            167
            B          38         11             12
            C          17         12             20

Decision: B. Edits — the per-interaction cost — are the fastest or tied
in every engine, and B is the only strategy whose 10-node edit stays flat
(A rewrites the whole sheet; C pays per-element style nodes and degrades
on multi-node edits). B's higher one-off install cost is paid once per
surface mount and is now also covered by the server-rendered first sheet.
All three strategies cleaned up with no leftover <style>.

  Undo/Redo of a committed drag
    latency median / p95 (ms)      71 / 87.6     77.6 / 89.2   77.3 / 89.1

Reading:
- Interaction frame medians are unchanged (16.7 ms); p95 is within the
  run-to-run noise (after #2 equals before).
- Style recalculation on first render fell ~60% (27 → 10–11 ms): one
  class per element and :where() rules are cheaper than the Tailwind
  utility soup plus inline styles.
- Costs, small and consistent: ~+3 ms per Free resize step (≈ +5%) and
  ~+6 ms Undo/Redo median latency (the sheet sync of the replaced
  document runs inside the store write).
- Zero sheet mutations during every pointer move (5 of 5 drags and 5 of
  5 resizes, both runs) — the §8.11 property holds at scale.

jsdom (unit tests only, not production): with a real generated sheet,
jsdom's getComputedStyle — called by Testing Library for every role
query — walks the rules, so full-app jsdom tests run ~1.8–2× slower
(EditorApp catalog test 4.2 s → 7.3 s; with sheet insertion disabled the
time is back to HEAD's, so the compiler itself costs nothing measurable).
Three heavy tests got larger time budgets (Report 3). Production Chromium
shows no comparable cost (style recalc fell).

  Gradient stop drag, commit  Chromium    39     33       0            2
                              Firefox     39     33       0            2
                              WebKit      20     15       0            2

(WebKit frame interval median ≈ 120 ms on this machine: frame-starved,
known since BC-03; Chromium/Firefox 16.7 ms.)

Asserted in every engine:
- zero sheet mutations while live;
- the element follows the gesture every frame;
- after commit, no frame returns to the start geometry; every frame
  without the override paints one identical box (the committed geometry
  from the sheet); the hand-off never moves back toward the start (the
  final pointer move may land in the release frame — observed: last live
  frame y=293, committed y=295, the final pointer position);
- Escape: exact original box, override removed, sheet untouched;
- commit cost: 2 mutations (one base rule replaced) — 4 for a Flow
  resize, which also drops the paragraph's prose default.
