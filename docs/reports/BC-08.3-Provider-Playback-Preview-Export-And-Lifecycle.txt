1. EXECUTIVE SUMMARY
--------------------
Video Embeds now play in Preview and on exported pages, using one shared
player configuration (src/lib/videoEmbed/videoEmbedPlayerConfig.ts).

Design still shows the static placeholder and makes no provider request.
That is tested in 3 browsers, in Electron, and under stress.

Lifecycle:
- A player is mounted only while it is shown.
- It is removed, and its document with it, when:
  - Preview exits;
  - its element or ANY ancestor is hidden by an interaction;
  - an ancestor or the element itself has Display none / Visibility
    hidden.
- Showing it again creates a fresh player.
- Exported pages do the same through the export runtime.

Behaviour rules:
- Muted-only autoplay is enforced for every provider.
- Reduced motion suppresses autoplay in Preview and on exported pages.
- Browser fullscreen is delegated with allow="fullscreen", to provider
  players only. Generic Embeds and the desktop app get none.

Real players were checked against live providers (an opt-in suite, run
once in Chromium, Firefox, WebKit and Microsoft Edge):
- YouTube: VERIFIED. Plays, muted autoplay works, mute=1 and nocookie
  confirmed, fullscreen available; in Preview and on exported pages.
- Wistia: VERIFIED, the same.
- Vimeo: BLOCKED (decision needed). Its player shows "Unable to play
  video. Please try again in a supported browser." unless the frame is
  also given the encrypted-media permission. This happens with or
  without Layoutry's sandbox; adding only allow="encrypted-media"
  restores Vimeo's normal player.
  That permission is outside the approved policy, so Vimeo players are
  NOT loaded. Preview, export and the Inspector say why. Section 35 has
  the decision.
- Loom: UNVERIFIED. No public test video was available. The player is
  loaded under the same policy, and the Inspector says playback hasn't
  been confirmed.

Bugs found and fixed while testing:
- the Inspector lint error;
- several test-harness issues (section 28).

No product regressions.

Pre-existing issue recorded, not changed: WebKit leaves EVERY
aspect-ratio grid item (Image, Video, Embed, Video Embed) at a stale
height after a live window resize.

Validation:

- Firefox and WebKit targeted specs: 100/100.

4. SHARED PLAYER CONFIGURATION ARCHITECTURE
-------------------------------------------
src/lib/videoEmbed/videoEmbedPlayerConfig.ts:
  resolveVideoEmbedPlayerConfig(input, { hostOrigin, reducedMotion, fullscreenAllowed })
    -> { provider, src, stillSrc, autoplayRequested, title, sandbox,
         allow, referrerPolicy, loading } | undefined

It runs these steps:
1. Re-parses the stored src with the BC-08.2 parser
   (readVideoEmbedSource). A raw persisted URL is never trusted.
2. Returns undefined for:
   - an invalid or unsupported source;
   - a deferred provider;
   - a blocked provider (getVideoEmbedPlaybackBlocker).
3. Rebuilds the player URL from the validated identity
   (buildVideoEmbedPlayerUrl, BC-08.2), with:
     autoplay = authored autoplay AND muted AND the provider supports it
                AND NOT reduced motion
   stillSrc is the same player without autoplay.
4. Requires https on one of the provider's own embed hosts, with no port
   or credentials, for both URLs.
5. sandbox = resolveIframeSourcePolicy(src, hostOrigin): the unchanged
   BC-02.3 policy.
6. allow = "fullscreen" only if fullscreenAllowed and the provider is
   fullscreen-capable.
7. title = the authored title, else the provider's default.

Preview calls it with:
  hostOrigin = window origin
  reducedMotion = matchMedia
  fullscreenAllowed = !desktop app
Export calls it with:
  hostOrigin = EXPORTED_PAGE_ORIGIN
  reducedMotion = false (decided per viewer by the runtime)
  fullscreenAllowed = true
Nothing else builds a player URL.

Immutability: these are pure functions. Preview and export write nothing
(unit-tested: same document object, same history; browser-tested: Undo
stays unavailable, no "Unsaved changes").


5. PREVIEW RENDERING
--------------------
New component: src/features/canvas/components/document/elements/VideoEmbedFrame.tsx,
rendered by IframeElement for Video Embeds only.

Design:
- VideoEmbedPlaceholder, as in BC-08.2. The text is now "Plays in
  Preview. No video is loaded while you design".

Preview:
- An <iframe> is rendered when shown, i.e. when:
  - not RuntimeHiddenContext (the element or an ancestor hidden by an
    interaction, BC-02.5.1);
  - not isNodeAuthoredHidden (Display none / Visibility hidden on the
    element or an ancestor);
  - the host origin is known.
- Attributes: data-video-embed-player, src, title, sandbox, allow,
  referrerpolicy, loading, id, class.
- It is keyed on src + sandbox + allow, so a change always gets a fresh
  frame.
- Otherwise the placeholder is shown, or the blocker text for Vimeo.

Supporting hooks:
- canvas/hooks/usePrefersReducedMotion.ts
- canvas/hooks/useIsDesktopShell.ts (window.layoutryDesktop from the
  preload)
Both prerender to the strict value (reduce / desktop) until hydrated.

The Design MediaInteractionShield is unchanged; it renders nothing in
Preview.


6. EXPORT RENDERING
-------------------
buildExportDocument, Video Embed branch:
- valid and playable:
    <div class="…frame…">
      <iframe sandbox="allow-forms allow-popups allow-scripts allow-same-origin"
              src="<still URL>" title="…" allow="fullscreen"
              referrerpolicy="strict-origin-when-cross-origin" loading="lazy"
              data-ly-video-src="<authored player URL>"></iframe>
    </div>
  Both URLs also pass checkExportUrl(…, "frame").
- Vimeo (blocked): the empty frame, plus warning video-embed-blocked
  ("Vimeo videos can't play yet: … Its box is empty in the exported
  page.").
- No link or an invalid link: the empty frame, plus warning
  video-embed-invalid.
- Any player: one info per page, video-embed-needs-website ("Video
  players load from YouTube, Vimeo, Loom or Wistia: they need an internet
  connection, and some play only when the page is opened from a website
  (http or https), not as a local file.").
- Unmuted autoplay: warning unmuted-autoplay, the same as for <video>.

The runtime (exportInteractionRuntime.ts) is included whenever a player
is present (needsInteractionRuntime(behaviors, root)). Its rules:
- At load, a hidden or unrendered player is removed. A shown player is
  kept if its markup URL is already the right one; otherwise it is
  replaced by a fresh frame.
- Hiding (setVisible) removes every player not shown, using:
    isShown = not inside [hidden] or a closed dialog, and
              getClientRects().length > 0
- Showing creates a fresh clone of the original element:
  - from data-ly-video-src (autoplay as authored) unless the viewer
    prefers reduced motion, in which case the still src is kept.
  - New elements, not navigations, so no history entries.
- Without JavaScript the page shows the still player (no autoplay): the
  strict fallback.

The engine does not depend on the editor runtime.

8. SANDBOX AND PERMISSIONS
--------------------------
- Sandbox: identical to BC-02.3, from the same function.
  - allow-same-origin only because provider hosts are cross-origin.
  - None of the forbidden tokens appear (unit-tested over every
    provider).
- Permissions Policy: allow="fullscreen" only, on Video Embed players
  only, never in the desktop app.
  - No autoplay, encrypted-media, picture-in-picture, clipboard or other
    delegation.
  - Generic Embeds have no allow attribute (unit and browser tests).

- Vimeo needs a Permissions-Policy addition (encrypted-media), not a
  sandbox change. It was NOT made (section 35).


9. AUTOPLAY ENFORCEMENT
-----------------------
The required matrix is unit-tested for every playable provider, plus
the browser and export URLs:

  Autoplay  Muted  Requested?        Provider URL
  --------  -----  ----------------  ---------------------------------------
  off       off    no                no autoplay param (Vimeo/Wistia: explicit off)
  off       on     no                mute param only
  on        off    no, never muted   no autoplay param; warning in export
  on        on     yes, if allowed   autoplay=1 / autoPlay=true + mute

- "If allowed" means the provider supports it, it is not blocked, and
  the viewer has not asked for reduced motion.
- No allow="autoplay" delegation. Live, muted autoplay started without it
  for YouTube and Wistia in every engine.
- The Inspector says: "Starts by itself only when Muted is also on, and
  never for visitors who ask for reduced motion. Browsers and the
  provider can still block it."
- Muted is never switched on for the user (BC-08.2 tests still pass).

11. VISIBILITY LIFECYCLE
------------------------
Each of these is browser-tested in 3 engines, in Preview and on the
exported page:
- Hidden by Toggle on an ANCESTOR: the player is removed; its frame
  document is detached.
- Hidden at start (initialPreviewVisibility hidden): no player and no
  request until Show.
- Show, then Hide: mounted, then removed.
- Authored display:none ancestor: never mounted, never requested.
- Shown again: a fresh player, i.e. a new request starting at its
  configured start time. No position is kept.
- Repeated changes: 4 rounds (browser) and 30 cycles (stress). The
  player count and frame count always return to the expected values.

Interaction integrity:
- Duplicated or copied embeds are independent nodes. Each mounts its own
  player (BC-08.2 duplicate/paste tests plus the stress spec's six
  embeds).
- A deleted interaction target is BC-04's dangling-target handling,
  unchanged.
- Save/reopen keeps every setting (BC-08.2 tests, still green).


12. PREVIEW EXIT CLEANUP
------------------------
- Exit Preview unmounts every player. No provider frame remains, so no

13. HIDDEN ANCESTOR BEHAVIOR
----------------------------

- Both are unit-tested (VideoEmbedFrame and isNodeAuthoredHidden in

- Preview: from matchMedia.

19. LOCAL-FILE / REFERER LIMITATIONS
------------------------------------
- Hosted page (loopback http): the players receive Referer = the page
  origin (browser test, 3 engines, fake player).
- Local dev server (the editor): Referer = http://localhost:3000/.
- Exported page opened as file://: the player request carries NO Referer

- Offline: provider videos need the internet. The export info and the
  Inspector say so ("It plays from <provider>'s site, so it needs an
  internet connection."). Nothing claims offline playback.


20. ERROR HANDLING
------------------
- Empty, invalid or unsupported link: no iframe anywhere. Preview shows
  the placeholder; export writes the empty frame and a warning.
- Hostile stored values (evil hosts, javascript:, data:, user-info,
  ports, Twitch, Dailymotion): no player in Preview (unit-tested) or
  export (unit-tested).
- Provider-side failures (blocked embedding, private or deleted video,
  network down, Error 153): shown by the provider inside its own frame.
  Cross-origin, Layoutry cannot detect them and does not pretend to.
  There is no Layoutry loading state, so none can hang.
- Vimeo: blocked up front, with an explanation everywhere.

35. OPEN DEFECTS AND DECISIONS
------------------------------
D1  VIMEO PLAYBACK. Decision REQUIRED.
    Vimeo's player needs allow="encrypted-media" in addition to
    fullscreen. Without it, it shows "Unable to play video" (proven with
    and without the sandbox, in headed Edge).
    Options:
      (a) grant "fullscreen; encrypted-media" to Vimeo players only.
          This is a Permissions-Policy feature (Encrypted Media
          Extensions / DRM); it changes no sandbox token and no
          navigation rule. Privacy: it lets the frame use the browser's
          content-decryption module.
      (b) keep Vimeo blocked (current state).
      (c) remove Vimeo from the supported providers.
    Implementing (a) is a one-line registry and config change plus
    tests.
D2  GENERIC EMBED LIFECYCLE (BC-08.1 F5, generic part). NOT changed.
    A generic Embed (any page, including a video page) stays mounted
    across Preview exit and when hidden: BC-02.3's tested behavior
    ("repeated Preview sessions keep the same iframe").
    Media inside a generic Embed can therefore keep playing after
    Preview exits. Changing it would contradict an approved, tested
    behavior, so it needs authorization (CLAUDE.md conflict rule).
    Users who want lifecycle-managed video should use Video Embed.
D3  PRE-EXISTING WebKit layout. Low; not BC-08.
    After a live window resize, aspect-ratio grid items (all media)
    keep a stale height in headless WebKit. A reload fixes it. Real
    Safari was not verified.
D4  Reduced-motion autoplay rule for native <video>/<audio>, for parity.
    Product decision.
D5  Loom: needs a product-owned public Loom test video to verify
    playback.
