D. Windows icon generation
======================================================================
Pipeline: design/branding/brandIcons.mjs, run by
design/branding/generate-brand-assets.mjs (`npm run brand:generate`). It
uses sharp 0.34.5, already installed through Next.js and now pinned as an
explicit devDependency. No external service or icon CDN is used.

1. Backdrop removal. Starting from the image border, the generator flood-fills
   light pixels (all channels > 150) to transparent, which removes the
   white backdrop and gray shadow. The white page and glove inside the
   tile are enclosed by blue, so the fill never reaches them. The tile's
   outermost 1-px ring, which is blended with white, is kept at alpha 110
   to avoid a light fringe on dark taskbars.
2. The result is cropped square around the tile (1057 px master).
3. Sizes 32 px and up use the master, resized with Lanczos3. Sizes 24 px
   and below use the simplified variants (section E).
4. Entries are packed as a real multi-image ICO: 32-bpp PNG-compressed
   entries, with 256 stored as 0 in the directory. It is not a renamed
   PNG. The unit test checks that readIco() rejects a renamed PNG.

design/branding/layoutry.ico: 16, 20, 24, 32, 40, 48, 64, 128, 256 px
(220,717 bytes). Every entry decodes to its declared size and has alpha
(unit-tested). Output is deterministic: regenerating produced identical
bytes.

E. Small-size variants
======================================================================
At 16 and 24 px the downscaled artwork is unreadable: no brush and no code
symbol. This was checked on 6x-zoomed contact sheets on light and dark
backgrounds. Two pixel-grid SVGs, drawn from the artwork with its colors,
replace it at those sizes:
  layoutry-icon-small-24.svg  -> 20 and 24 px
  layoutry-icon-small-16.svg  -> 16 px
Kept: the blue→indigo rounded tile (cyan top-right), the white webpage
with its purple→blue hero band, the dark code window, and the
paintbrush (blue handle, silver ferrule, orange→purple tip).
Simplified (also listed in design/branding/README.md):
  - The hand is dropped. The brush's white grip end stands in for the
    glove.
  - Page content is reduced to the hero band and two blocks. The browser
    dots, mountains, "T" box and dashed placeholder are gone.
  - The code window shows `</>` at 24 px and only `< >` at 16 px (the slash
    does not fit in 4 px).
  - The design→code arrow and one back page layer are kept at 24 px and
    dropped at 16 px.
The result is clearly the same identity at a glance: blue tile, white
page, brush, code window.

W. Known limitations
======================================================================
W1. In the packaged build, the 16 px title-bar icon is Electron's
    downscale of the large icon, not the simplified 16 px variant.
    Electron only picks exact .ico entries when BrowserWindow.icon is a
    loose .ico file, and Windows' LoadImage cannot read inside app.asar.
    Shipping a loose .ico would change the verified resources/ layout
    (only app.asar), so it was left out of scope. Development runs do show
    the simplified 16 px icon.
W2. The taskbar button (~24 px at 100 %) shows the 32 px artwork scaled by
    Windows, not the simplified 24 px variant, in both packaged and dev.
    This is Windows behavior for window icons. Recognizable, but busier
    than the 24 px variant. Explorer/file views of Layoutry.exe use the
    exact 16/24 entries.
W3. The tab favicon was verified by emitted links, served files and
    decoded contents, not by viewing a real browser tab strip.
W4. Only 100 % display scaling is available on this machine (Win10, one
    monitor). The 20/40 px entries for 125 % scaling are present but not
    seen live.
W5. LayoutryLogoMark.tsx duplicates layoutry-icon-small-24.svg (noted in
    both files). Changing one requires changing the other.
W6. Derived icons are committed binaries, regenerated by
    `npm run brand:generate`. They are not rebuilt automatically when the
    source changes. Packaging validates the .ico's sizes but not its
    freshness.
