- What was done:

2. ROOT CAUSES OF FIXED DEFECTS
-------------------------------
- BC-05-C:
  - useInspectorEditSession ends an open session on any pointerdown
    outside its input, with "commit" (BC-01.3).
  - A reset button press therefore committed the half-typed draft as its
    own merged history entry, before the reset's entry.
  - Measured in BC-05.1: 40 → type 55 → Reset; Undo → 55.
- BC-05-D:
  - InspectorResetButton is disabled and invisible when there's nothing
    to reset (opacity-0, pointer-events-none).
  - Activating it usually makes it disabled, so the browser drops focus
    to <body>.
- BC-05-E:
  - The flowLayout container settings, flexChild and gridChild are full
    records (every field required).
  - Their sections had no notion of "authored", and the commands couldn't
    remove the item records.
- BC-05-F:
  - The section exposed only the whole-group reset, although
    withTransformField/normalizeTransformSettings already supported
    per-field removal.


3. WIDTH/HEIGHT ISOLATION CHANGES
---------------------------------
Model (unchanged):
- EditorElementNode.dimensions = { preferredWidth, preferredHeight,
  offsetX, offsetY }, all required (editorDocumentSchema).
- elementDimensionsStyle writes width + height + flex-shrink: 0 together.
- Committing one axis in the Inspector seeds the other from the rendered
  size. That was the documented Checkpoint 5.7 audit decision.

Done:
- Both reset buttons are now labelled "Reset width and height" (accessible
  name and tooltip).
- A code comment records why.
- Behavior is unchanged: removing the record returns both axes to Auto,
  and the offsets to 0. Free children keep no size reset, because their
  geometry is required.
- Min/Max Width/Height: each resets only its own field. Verified by unit
  test (reset Min width keeps Max width, Min height and Max height; reset
  Max height keeps the rest; Undo restores).
- Size constraints are a separate record, untouched by the size reset
  (tested).

Not done: true per-axis reset (blocker, section 17).

Test combinations from brief §4, as they apply to the current model:
1. Both authored: the reset clears both, as the label says (unit).
2/3. Only one authored: impossible in this model, because both axes are
   always stored together.
4. Repeated reset: the second press is impossible (the button is
   disabled once there's no record).
5. Undo/Redo: restores the whole record (existing tests plus history
   semantics).
6. Free layout: no size reset (existing test).
7. Constraint isolation: tested.


4. ACTIVE-EDIT TRANSACTION POLICY
---------------------------------
Policy:
- A reset that covers the field being edited cancels the edit (Escape
  semantics), then removes the value.
- Any other reset, or anything else, commits the edit as before.

"Covers":
- New markers: each InspectorResetButton carries data-inspector-reset.
- The components that can hold one carry data-inspector-reset-scope:
  InspectorPropertyRow, InspectorSegmentedRow, InspectorNumberFieldRow,
  InspectorColorFieldShell, InspectorSection.
- A reset covers its nearest scope:
  - its row;
  - or the whole section, for a section-level reset such as "Reset
    transform" or "Reset flex item".
- utils/inspectorResetScope.ts (isResetCovering).

Where:
- useInspectorEditSession's capture-phase pointerdown handler:
  - if the target is a covering reset → endSession("cancel");
  - otherwise "commit", unchanged.
- Cancel is the existing BC-01 path:
  - restore the pre-session document;
  - cancelTransaction, so no entry is recorded;
  - the draft resyncs.
- Then the click performs the reset as one ordinary history entry.
- No new history mechanism was added.

Coverage (every control built on useInspectorEditSession):
- InspectorNumericValueControl (Typography sizes, Transform, Size,
  Position, Filters, etc.);
- InspectorNumberFieldRow (Flex/Grid gaps, Flex item, Grid item);
- InspectorSliderField's exact-value box (Gap, Opacity, etc.);
- InspectorColorFieldShell's text field (all colours).

Other controls:
- Native colour picker: commits only on its change event, one entry; no
  open session to collide with.
- Slider drag: the pointer is captured by the slider, so a reset can't be
  pressed mid-drag.
- Segmented controls and selects: one-shot commits.

Guarantees and evidence (unit tests in InspectorResetBehavior.test.tsx,
plus e2e):
- No intermediate entry: typed 55 + Reset → history +1 only.
- No stale value:
  - the field shows the reset value;
  - a later blur commits nothing (history unchanged).
- No duplicate commit: as above.
- Undo restores the pre-edit authored value (20 / 40 / #112233 / gap 12);
  Redo reapplies the reset.
- An unset property typed into and reset ends unset, with zero history.
- A reset of a different property still commits the draft first (2
  entries). That is deliberate: moving on keeps the edit.
- Escape then Reset: Escape restores, then the reset removes; 1 entry.
- Enter commits as before.
- Keyboard: Tab from the field to Reset commits on blur (the BC-01
  rule); the reset is then its own step.
- Selection change: the session commits as before (BC-01). Reset
  controls follow the newly selected element (e2e "selection changes").
- Regression proof: with the committed (HEAD) hook, 5 of these unit tests
  fail; with the fix they pass.

Text-based CSS fields (background image URL, font family): they don't
use live edit sessions (commit on Enter/blur), so there is no draft to
discard.


5. KEYBOARD FOCUS BEHAVIOR
--------------------------
InspectorResetButton:
- On a keyboard activation (Enter/Space: a click with detail 0), after
  the reset renders:
  - if focus was lost (body, or the now-disabled button), it moves to
    the covered scope's control, via resetFocusTarget.
- resetFocusTarget picks the first selected segmented option or
  text/number/select field in document order (not the native colour
  input).
  - For a section-level reset, that is the section's first property.
  - It never picks a reset button or a help icon, and skips a collapsed
    (inert) section body, falling back to the section header.
- A pointer click leaves focus alone, so no surprise focus ring for mouse
  users.
- If the button is still enabled after the reset, focus stays on it.

Measured:
- Chromium, Firefox, WebKit, Electron: Enter on "Reset font size" → the
  Font size field is focused.
- Space on "Reset text alignment" → focus stays in the Align row (its
  selected option).
- Shift+Tab / Tab from there stay inside the Inspector. No trap.
- Disabled reset buttons stay out of the Tab order (native disabled), as
  before.
- No artificial keep-visible.


6. FLEXBOX/GRID RESET COVERAGE
------------------------------
Semantics:
- These are full records: every field is stored and always written to
  CSS by resolveFlowLayoutStyle / resolveFlexOrGridChildStyle.
- "Authored" = differs from the model default (DEFAULT_FLEX_SETTINGS,
  DEFAULT_GRID_SETTINGS, DEFAULT_FLEX_CHILD_SETTINGS,
  DEFAULT_GRID_CHILD_SETTINGS, now exported from types/flowLayout.ts).
- Reset writes that default: exactly what the getters return when nothing
  was ever set, so the CSS equals the never-edited state.

| Section | Control | State field | Reset |
| --- | --- | --- | --- |
| Content Layout (Flex) | Direction | flex.direction | "Reset direction" → row |
| | Wrap | flex.wrap | → nowrap |
| | Justify content | flex.justifyContent | → start |
| | Align items | flex.alignItems | → stretch |
| | Gap (linked) | rowGap + columnGap | "Reset gap" → 0/0 |
| | Row gap / Column gap (unlinked) | one each | own reset → 0 |
| Content Layout (Grid) | Columns | grid.columns | → 2 |
| | Rows | grid.rows | → auto |
| | Row gap / Column gap | one each | → 16 |
| Flex item | Grow, Shrink, Basis, Align self | flexChild.* | per field → 0, 1, auto, auto |
| | (section) | flexChild | "Reset flex item" removes the record |
| Grid item | Column start, Column span, Row start, Row span | gridChild.* | per field → auto, 1, auto, 1 |
| | (section) | gridChild | "Reset grid item" removes the record |

Notes on the table:
- Grid model defaults are Layoutry's (2 columns, 16 px gaps), not CSS
  initial values. They are what a container gets on switching to Grid.
- Flex/Grid item: once every field is back at its default, the record
  itself is removed.
  - It matters for Flex: a resized element WITHOUT a record doesn't
    shrink (resolveFlexOrGridChildStyle), so removing the record, rather
    than writing shrink 1, restores the original behavior.
- The commands setFlexChildSettings / setGridChildSettings now accept
  undefined and delete the key.
- Basis and Column/Row start "Fixed" toggles resync when reset.

Structural exceptions (no reset, by design):
- Layout mode (Flow/Free), Display (Block/Flex/Grid): structural choices
  of how children are laid out; there is no override to remove.
- Resize contents, Snap: editor behavior, not CSS.
- Align content: in the model, but no control exists. Not added (no new
  CSS controls).
- Order, explicit grid templates and grid-column/row strings: not
  implemented in the repository, so not added.

Component stamped values: compositions (cards, button groups, etc.) stamp
flex settings as authored data. Their resets return to the model default,
consistent with how every other group treats stamped values. Undo
restores.


7. TRANSFORM RESET GRANULARITY
------------------------------
- Representation: structured TransformSettings { translateX?, translateY?,
  rotateDeg?, scale? }. No string parsing.
- Per-field reset uses the existing withTransformField(current, field,
  undefined) → normalizeTransformSettings (drops the field and identity
  values, collapses to undefined).
- Each row shows the "set" state dot and its own reset.
- "Reset transform" (section) is kept.
- Multi-selection "Reset transform" (bulk) is unchanged.
- Skew and other operations: not implemented in the repository.

Measured:
- Rotate 20 + Scale 1.5 → Reset rotate → computed transform =
  matrix(1.5, 0, 0, 1.5, 0, 0) (scale only), and the Scale field still
  shows 1.5.
- Undo restores the rotation; Redo removes it again.
- Electron: Rotate 15 + Scale 2 → reset → matrix(2, 0, 0, 2, 0, 0).

17. KNOWN LIMITATIONS
---------------------
- BC-05-B blocker: per-axis width/height reset needs dimensions to allow
  one axis to be absent. Options:
  (a) optional preferredWidth/preferredHeight in the schema + resolver +
      resize engine + Inspector.
      - Backward-compatible read; older builds can't read new files;
        needs a format version bump and migration tests.
      - Medium-large: the resize engine and the free-layout conversion
        read both axes.
  (b) Keep the atomic model, with one "Reset size" control instead of two
      identical buttons.
      - Small; honest; no format change.
  Recommended: (b) now. Schedule (a) only if per-axis Auto sizing is a
  product goal.
- Two buttons share the name "Reset width and height". Duplicate names are
  legal but repetitive for screen readers. Option (b) would remove the
  duplicate.
- The explanatory reset sentence from BC-05.1 isn't shown anywhere (no
  shared slot without per-row prose).
- Layout field "authored" = differs from the model default: a value
  deliberately set to the default reads as not set. This is inherent to
  full-record models.
- Multi-selection: unchanged.
  - Bulk resets still exist only for Transform and Transition.
  - The other bulk sections have none (BC-05.1 R6).
- WebKit specs run serially (environment).
