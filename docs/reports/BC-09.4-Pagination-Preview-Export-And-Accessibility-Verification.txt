5. EXPORT VERIFICATION
----------------------
Markup of a managed Pagination (8 pages, First/Last, ellipsis, page 4
current):
- <nav aria-label="Pagination">;
- First, Previous, 1, 2, 3, 5, 6, 7, 20, Next and Last are <a href>;
- 4 is <a aria-current="page"> with no href;
- "…" is <p aria-hidden="true">;
- no <script> and no script.js.
- Standalone and separate files: the same <nav> markup (one serializer;
  unit test). Browser ZIP and the Electron folder package those same
  files; packaging code is unchanged, so it was not retested.
- Valid nesting: phrasing elements in <nav>, as in BC-09.2.
- Disabled is checked by behaviour, not by aria-disabled alone:
  - no href, so nothing to follow;
  - not a trigger, so the runtime ignores it (BC-09.2.1 and BC-09.3
    tests);
  - with JavaScript off, clicking it doesn't navigate (BC-09.2 spec).

----------------------------

  the last page.
  - Evidence: paginationCommands.test ("first(off)", "last(off)"

  - New: the browser accessibility tree shows "First"/"Previous" as

8. ENABLED NAVIGATION
---------------------
- Pages use their authored destinations.
- Previous and Next point at the adjacent pages, First and Last at the
  ends (BC-09.3 command, store and Chromium tests; new: the a11y spec's
  managed document).
- A missing or invalid adjacent destination disables the control
  (paginationCommands.test).
- Unsafe URLs are refused at the Inspector (isValidLinkHref plus the
  export policy), at the schema, and again at export.
- Enabled links keep native behaviour (Tab, Enter). Their authored
  interactions still run (BC-09.3 page 5 tests).
- No content switching.


9. ELLIPSIS ACCESSIBILITY
-------------------------
Investigation:
- the BC-09.3 markup was <p>…</p>, which screen readers announce
  ("horizontal ellipsis" / "dot dot dot");
- it is a non-focusable paragraph with no role.
Options:
A. A stored aria-hidden field: format 4 (strict schema) — refused, not
   needed.
B. A derived attribute from the component context (chosen): the
   Pagination already identifies its ellipsis (role label + marked
   parent), exactly like the Dialog's derived aria-label.
   - resolveDerivedAccessibilityAttributes(node, parent) is the single
     source.
   - The export applies it in buildChildren; the Canvas applies it in
     ParagraphElement (parent looked up only for a paragraph labelled
     "Ellipsis").
   - No schema change.
- aria-hidden is appropriate: the element is decorative and contains
  nothing focusable or operable.
- Scope: only a marked Pagination's ellipsis. Breadcrumbs "/"
  separators and an unmarked nav's "…" are unchanged (unit test), so
  legacy output is byte-identical (the frozen legacy export test was
  rerun and passes).
- Verified: the export's accessibility tree contains no "…" in
  Chromium, Firefox and WebKit, while it stays visible.


10. INSPECTOR EXPLANATIONS
--------------------------
Pagination section, Controls group:
- "Navigation destinations update automatically when the current page or
  page URLs change. First, Previous, Next and Last are disabled where
  they would lead nowhere."
- "Hiding a navigation control removes it. Showing it again restores its
  default label, styled like the other navigation controls."
  (Accurate to the BC-09.3 behaviour: the label resets and the look
  comes from the opposite control.)
"In this Pagination" note on a selected child (InspectorPaginationChildNote):
- disabled control: doesn't navigate, interactions don't run in Preview
  or Export, becomes active when the current page changes;
- current page: intentionally not a link and not activatable;
  destination kept;
- ellipsis: decorative, skipped by screen readers, no interactions;
- enabled Previous/Next/First/Last: the destination is set automatically.
- Nothing for ordinary pages or for non-Pagination links.
Interactions section: when the element can't activate and has
interactions, "These interactions won't run: …". Nothing is removed and
editing stays possible.
All of it uses the existing 11px help-text style and InspectorSection.
No redesign.
