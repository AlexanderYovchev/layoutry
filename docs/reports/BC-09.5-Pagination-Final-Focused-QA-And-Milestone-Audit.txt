1. EXECUTIVE SUMMARY
--------------------
The audit found TWO High defects. Both were reproduced, fixed with
regression tests, and proven by switching each fix off.

H1 — a drag-move replaced another Pagination's current page.
- Dragging Pagination A's current page into Pagination B made it B's
  current page and demoted B's own current page.
- This broke the approved rule "copying a current page into another
  Pagination must not replace that Pagination's existing current page".
  Copy/paste was protected (BC-09.3); drag-move (moveElement) was not.
- Fix: a current page that leaves its parent stops being current, the
  same as a pasted copy. It takes the destination's ordinary look, and
  its old Pagination promotes a new current page, in the same Undo step.

H2 — a BC-09.2 Pagination could be structurally misread.
- A Pagination saved by BC-09.2 (no role labels) was read positionally
  (first and last link = Previous and Next). After its Previous was
  hidden in the Inspector or deleted on the Canvas, the fallback ran
  again on the CHANGED structure: page 1 became a disabled "Previous"
  and page 2 the current page. That corrupts a real project.
- Fix: role labels are always taken from the Pagination BEFORE an edit
  (labelPaginationRoles). The fallback is therefore only ever applied
  to the structure it was designed for.
- Tested on the frozen BC-09.2 fixture, loaded exactly as a real open.

Everything else holds:
- the component identity;
- the one-current-page invariant (now including drag-move);
- current-page and disabled safety in Preview and Export;
- Preview/Export parity;
- no Pagination JavaScript;
- format 3 safety;
- legacy preservation;
- responsive wrapping.

Recommendation: CLOSE BC-09 after QA confirms these two fixes (section
21).

6. CURRENT-PAGE INVARIANT AUDIT
-------------------------------

- remove current → page before is current (09.3);
- remove first while page 2 is current → page 2 (renumbered "1") stays
  current (probe);
- remove last current → previous page (09.3 commands test);
- cut current → neighbour promoted; paste back → original current again
  (09.3);
- paste or copy into another Pagination → ordinary there; its current is
  kept (09.3);
- duplicate current → an ordinary copy (09.3);
- drag-move into another Pagination → was BROKEN (H1); fixed, with a
  test;
- reorder inside its own Pagination → stays current (new test);
- Undo/Redo after a current-page change → restores the state, styling
  and boundaries (new lifecycle test);
- save/reopen after a change → identical; the current page keeps its
  stored destination (new lifecycle test).
Styling and aria-current stay synchronized: the state look moves with
aria-current (09.3 tests; 09.5 checks the look on H1).
The stored destination is preserved while current and renders again
when ordinary (09.3 commands test; 09.5 lifecycle: the reopened current
page keeps "/p/4").
