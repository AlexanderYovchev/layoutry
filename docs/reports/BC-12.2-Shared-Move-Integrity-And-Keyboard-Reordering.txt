3. SHARED MOVE COMMAND CHANGES
------------------------------
Single source of truth. The existing moveNode (documentCommands.ts) is
still the only tree mutation. It removes the node and re-inserts the SAME
object, so the id never changes. planMove wraps it:
  1. structural rules: getMoveTargetRejection
     - self, page, beside-page, descendant, not-found, incompatible-parent;
     - the old isValidMoveTarget logic, now with a reason;
  2. destination: resolveMoveDestination
     - before/after a sibling, or appended inside;
     - the parent plus the index once the element is taken out;
  3. no-op check (section 4);
  4. component rules (sections 6 and 9);
  5. geometry for a new parent (sections 5 and 7), written to the node
     BEFORE moveNode, in the same document;
  6. moveNode.
validateMove is the same rule set without the mutation.
Consumers:
- Canvas drop indicator (resolveActiveDropIndicator) → validateMove, so a
  refused move never shows an indicator.
- Canvas drop (useMoveElement) → the structural pre-check (silent, as
  before), then store.moveElement. A component refusal reaches the store,
  which shows a notice.
- Structure keyboard (StructureTree.handleReorder) → store.moveElement.
- store.moveElement:
  - planMove;
  - then the existing BC-09.5 current-page handling and
    withPaginationInvariants;
  - then pushHistory once, with the moved element selected.
  It returns {moved, leftLabel} | {unchanged} | {rejected, reason}. The
  return type changed from void; existing callers ignore it.


4. NO-OP DETECTION (G1)
-----------------------
- The destination index is normalized to the children list WITHOUT the
  moved element.
- A move is a no-op when the parent and that index equal the element's
  current parent and index.
- This is checked before any mutation. The store returns {} (same document,
  no history, not dirty, selection unchanged, no notice) and reports
  {status: "unchanged"}.
Tested:
- A before B when already before;
- B after A;
- C inside its own parent when already last;
- B before C;
- a real same-parent reorder still moves;
- moving the first child "inside" its own parent appends it.


5. FREE-CONTAINER POSITIONING (G2, D8)
--------------------------------------
Entering a Free parent (a different parent):
- Size: the element's existing freeLayout size (e.g. from another Free
  container, or an inert one from earlier), otherwise its tag default
  (getDefaultFreeElementSizeForNode). This is the same rule as
  insert/paste/duplicate.
- Bounds: if that size exceeds approximateFreeContainerSize(destination),
  the move is refused ("free-bounds"). The element is never shrunk or
  distorted, matching BC-10.5.1's group rule. Atomic: no change, no history,
  a notice with the reason.
- Position: resolveFreeDestinationPlacement, the existing one-shot helper.
  It takes the first free slot (never exactly on top of an existing child)
  and normalizes into the bounds.
Same Free container: coordinates are untouched; only the DOM / paint order
changes. Verified on the Canvas: the element on top changes, and both boxes
measure identically before and after.
Flow sibling reorders never add geometry.
Free → Flow: freeLayout is kept (inert in Flow, as paste already does), so
moving back restores the size.
Undo restores the element without the position.


6. NAVBAR CAPACITY (G3)
-----------------------
- A link entering a nav (a different parent) uses the existing BC-06
  contract, canAddNavigationLink with MAX_NAVIGATION_LINKS. No second
  constant.
- Full nav: refused ("navigation-link-limit"), atomically, with a notice
  "… a navigation bar can have at most 12 links".
- Reordering inside the full nav is allowed. Moving a link out is allowed.
- The link object is unchanged (identity, styling, interactions).
- Paginations are not navbars (isNavigationLinkContainer excludes them).


7. FLEX/GRID CHILD SETTING BEHAVIOR (G4)
----------------------------------------
Finding:
- resolveFlexOrGridChildStyle (shared by Canvas, Preview and Export) applies
  flexChild/gridChild only when the immediate parent is Flex/Grid.
- The Flex item / Grid item Inspector sections show only under such a parent.
- Copy CSS uses onlyOffered (BC-11.4).
- So stale settings are already inert everywhere and are deliberately KEPT:
  no data loss, and they apply again if the element moves back.
Real risk found and fixed:
- A Grid placement entering a SMALLER grid, e.g. column 4 in a 2-column
  grid, would create an implicit track (visible overflow).
- On entering a Flow Grid parent, gridChild is clamped by the existing
  clampGridChildPlacement, the same rule used when a grid's track count
  shrinks.
- Tested: column 4 span 3, row 2 → column 2 span 2, row 1 in a 2×1 grid.
No migration.


8. STRUCTURAL VALIDATION
------------------------
Supported: before/after a sibling, inside a compatible container,
cross-parent, out of a nested container, same-parent reorder.
Refused before any mutation, each with a reason code and message:
  self                 an element onto itself
  page                 the page root itself
  beside-page          before/after the page root
  descendant           into its own subtree (cycle)
  not-found            stale ids
  incompatible-parent  the canParentAcceptChild allowlists (li only in
                       ul/ol, cells in rows, rows in sections, option in
                       select, nothing inside leaves)
All seven cases are tested (no history, same document).


9. SPECIALIZED COMPONENT SAFEGUARDS
-----------------------------------
- Pagination (BC-09):
  - First / Previous / Next / Last and the ellipsis can't be moved
    ("pagination-control"), including the BC-09.2 positional fallback
    roles;
  - a page may not land before First/Previous or after Next/Last
    ("pagination-order");
  - a link entering a Pagination becomes a page and respects
    MAX_PAGINATION_PAGES (12, "pagination-page-limit");
  - withPaginationInvariants still keeps exactly one current page, and the
    BC-09.5 rule for a current page leaving its Pagination still applies;
  - component identity is unchanged.
- Navbar: section 6.
- Tables, lists, select: the existing tag allowlists (section 8).
- Forms / labels:
  - the model has no `for` attribute; a label names the control it
    contains;
  - moving a form control (input/select/textarea, or a subtree containing
    one) out of its nearest label is allowed, with a notice ("Email Input
    moved out of its label, so that label no longer names it."), per the
    approved D9 option A;
  - a reorder inside the same label is silent.
- Interactive elements and media: no special rule. A leaf can't contain
  children, and interaction targets are ids, which never change.
- Element identity: a move keeps the id, HTML id, class, text, styles,
  children, interactions and component metadata (deep-equal before/after in
  tests). No clone, no new id.


10. KEYBOARD REORDER BEHAVIOR (D11)
-----------------------------------
Each key moves the FOCUSED row:
  Alt+ArrowUp     before the previous sibling
  Alt+ArrowDown   after the next sibling
  Alt+ArrowRight  inside the immediately preceding sibling, as its last
                  child (refused with the reason if it can't contain it)
  Alt+ArrowLeft   right after the current parent
- "Preceding compatible element" is read as the immediately preceding
  sibling. Searching further back would also jump over the skipped
  elements, which is not what an outliner indent does. If that sibling
  can't contain the element, the move is refused and announced.
- Unavailable (no mutation, announced):
  - first/last child;
  - no previous sibling;
  - already at the top level;
  - the page row.
- Exact modifiers: Alt alone (Option on macOS). Ctrl+Alt, AltGr, Alt+Shift
  and Alt+Meta are ignored.
- The handler is on tree rows only, so Inspector fields and the rest of the
  app are unaffected.
- preventDefault stops the browser's Alt+Left/Right Back/Forward while a
  row has focus (verified in Chromium, Firefox and WebKit with a real
  history entry).
- Plain Up/Down/Home/End are unchanged.
- New plain Left/Right (WAI-ARIA tree):
  - Right opens a closed branch, or steps to the first child;
  - Left closes an open branch, or steps to the parent.
- Clipboard and selection shortcuts (Ctrl/Cmd+C/V/X/D, Ctrl/Cmd+Alt+C/V,
  Ctrl/Cmd/Shift+click) don't use the arrows. Untouched.


11. FOCUS AND SELECTION
-----------------------
- Only the focused row moves. With a multi-selection, the other selected
  elements stay put (tested).
- The moved element becomes the sole selection (the existing moveElement
  contract, D14).
- Focus returns to the moved row after the re-render. A row moved to
  another parent is a new DOM element, so a pending-focus effect focuses it
  and scrolls it into view.
- The destination's ancestors are expanded, so a move into a collapsed
  container opens it (tested).
- Unrelated branches keep their state. Hidden descendants never become
  targets: moves are computed from document siblings, and focus only lands
  on the moved row.
- No Shift-range is triggered. selectionAnchorId follows the existing
  selectionFromSingle.


12. ACCESSIBILITY ANNOUNCEMENTS
-------------------------------
- A polite live region (role=status, sr-only) in the Structure panel,
  separate from the selection-count region.
- Messages are read from the document AFTER the move:
  - "Moved Para A after Para B, position 2 of 2 in First section."
  - "Moved Para B to the start of First section, position 1 of 2."
  - Refused: "First section wasn't moved: that place can't contain this
    kind of element."
  - Unavailable: "Title is already first in Page." / "… is already last
    in …" / "… is already at the top level." / "There is no element before
    … to move it into."
  - No-op (only reachable by a stale request): "… is already there."
- Identical consecutive messages are re-announced (an alternating trailing
  no-break space).
- Refusals also show the shared notice banner (itself a polite status). A
  screen reader may hear a refusal twice; see limitations.


13. UNDO/REDO
-------------
- One move = one history entry (a whole-document snapshot).
- Undo restores the parent, the order and (after Free entry) the
  position-less element. Redo restores the destination.
- Geometry (Free position, Grid clamp) is written in the same document as
  the move, so there is no extra entry.
- Refused and no-op moves create no history.
- Selection after Undo/Redo follows the existing snapshot contract. No
  selection is persisted (no new store field; the persistence
  classification test passes).

17. PERFORMANCE CONSIDERATIONS
------------------------------
Cost per move:
- a few O(n) lookups (findNodeById/findParentId), no full-tree clone;
- moveNode/insertNode keep structural sharing;
- exceedsNavigationLinkLimit's full scan is NOT used; the Navbar check is
  O(children).
Indicator validation (validateMove) runs per drag-over. That is a handful
of O(n) lookups, unchanged in complexity from isValidMoveTarget.
Tested: a 40-level-deep subtree plus a 1,000-child container. Two moves
finish well under 1s (assertion < 1000 ms) with two history entries. No
element-count cap. No virtualization.
Not done (deferred to BC-12.3, where drag hover makes it matter): memoizing
Structure rows (React.memo with stable callbacks). Rows still re-render on
each document change, as before.

19. REMAINING LIMITATIONS
-------------------------
- Pointer drag in Structure (D1–D4, D10, D12, D13) and multi-element drag
  (D5/D6) are not implemented (BC-12.3 / later).
- Free bounds use approximateFreeContainerSize (the known BC-10.5.1/BC-11
  approximation).
- Paste/duplicate into a Pagination still don't enforce the 12-page limit
  (pre-existing; moves do now). Raised, not changed.
- A refusal is announced both by the Structure live region and by the
  notice banner (both polite). Possible double speech; low impact.
- The Canvas still gives no notice for a STRUCTURAL invalid drop (no
  indicator, silent, unchanged).
- Alt+Left Back prevention was checked with Playwright's synthesized keys.
  The Electron desktop shell was not run (no desktop code changed; it has
  no Alt+Arrow accelerators).
- Structure rows are not memoized (section 17).
- Style protection (Lock child styles) does not block structural moves.
  Geometry written on Free/Grid entry follows the same rule as paste
  (pre-existing behaviour).
